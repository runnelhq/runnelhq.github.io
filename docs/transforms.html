Entwicklerdoku · Bausteine

Einen neuen Transform entwickeln

Transforms sind die Bausteine von Pipelines: Sie lesen Datensätze (Records), verändern, filtern oder schreiben sie – als Strom, mit konstantem Speicher auch bei Millionen Zeilen.

Quelle: docs/dev/TRANSFORMS.md · Grundlagen: ADR 0007 (Typsystem), ADR 0013 (Namensräume).

Ergänzt die Actions-Anleitung

Namensräume, Konfiguration (with:), Schema-Tags, Texte, Windows-Besonderheiten und Dokumentation gelten wie in Actions entwickeln. Hier steht nur, was bei Transforms anders ist.

Beispiele im Repository: internal/transforms/core/ – generate.go (Eingabe ohne eingehende Links), dummy.go (reicht weiter), log.go (Konfiguration, Log); internal/transforms/csv/ – Datei lesen und schreiben mit Positionen in Fehlern, temporärer Datei und Kodierungen.

1. Aufbau

Aufbau
internal/transforms/<namensraum>/
  register.go          # eine Zeile je Transform
  <name>.go            # der Transform
  <name>_test.go       # seine Tests
  • Eigene Registry, getrennt von den Actions: derselbe Typname darf als Action und als Transform existieren (z. B. core.log). Ein neuer Namensraum wird in internal/transforms/transforms.go eingetragen.
  • Kategorie (transform.Category…): input, transform, flow, execution, combine, output.
  • Konfiguration wie bei Actions mit transform.DecodeConfig und den Tags doc und schema. Felder, die ${…} enthalten dürfen, als string anlegen – auch Zahlen wie rows. Der Wert wird in Process geprüft, nicht in New: runnel validate ruft New mit den Variablen, wie sie in der Datei stehen.
  • Für den Editor: Namen vorhandener Felder der eingehenden Datensätze mit schema:"format=runnel-field" (auch an Listen wie groupBy), Ziele von Daten-Links mit format=runnel-target, Eigenschaften, die nur für einige Werte einer anderen gelten, mit only=<feld>:<a>|<b>. Namen neuer Felder bleiben ohne Format.
  • Jeder Transform mit Konfiguration bekommt ein Example (die with:-Werte in YAML) für die Hilfe im Panel; der Vertragstest prüft, dass New es annimmt.

2. Verarbeiten (Process)

Beispiel: Text in Großbuchstaben
func (t *upper) Process(ctx context.Context, in <-chan transform.Batch, out *transform.Output) error {
	for b := range in {                 // bis alle eingehenden Links beendet sind
		for _, r := range b {
			v, _ := r.Get(t.Field)
			r.Set(t.Field, strings.ToUpper(fmt.Sprint(v)))
			if err := out.Emit(r); err != nil {
				return err              // Pipeline abgebrochen
			}
		}
	}
	return nil
}
ThemaRegel
Eingabein liefert Batches, bis alle eingehenden Links beendet sind; bei mehreren Links gemischt. Ein Transform ohne eingehende Links (Eingabe) bekommt einen geschlossenen Kanal und erzeugt Records selbst.
Ausgabeout.Emit(r) je Record; die Engine bündelt zu Batches und gibt jeden Record an alle ausgehenden Links (ab dem zweiten als Kopie). Einen Record nach Emit nicht mehr ändern. out.EmitTo(id, r) gibt ihn nur an den Daten-Link zu einem bestimmten Transform (Beispiel switch.go).
BackpressureEmit blockiert, solange die folgenden Transforms beschäftigt sind – nichts selbst puffern, sonst steigt der Speicher.
AbbruchEmit gibt bei Abbruch einen Fehler zurück: sofort zurückgeben. Bei langen Schritten ohne Emit (z. B. Datei öffnen) ctx weitergeben.
FehlerEin Fehler aus Process hält die ganze Pipeline an. Kann ein einzelner Record nicht verarbeitet werden, out.Fail(r, feld, err) aufrufen: mit Fehler-Link geht der Record dorthin (mit _error, _errorField, _errorTransform), sonst gibt Fail den Fehler zurück. Dazu RecordErrors: true in der Definition; out.HasErrorLinks() sagt, ob ein Fehler-Link da ist.
Frühes EndeEin Transform darf aufhören, bevor in leer ist; die Engine verwirft den Rest.
RecordsGeordnete Felder (internal/record): Get, Set, Delete, Clone; Namen mit _ sind für Metadaten reserviert. Werte als string, int64, decimal.Decimal, float64, bool, record.Date, time.Time, []byte, map[string]any/[]any; fremde Werte mit record.Normalize umwandeln.
Logout.Logf: Info für Ergebnisse, Debug für Details; bei großen Datenmengen nie je Record auf Info.
ZustandEin Transform-Objekt läuft in genau einer Goroutine; Zustand im Objekt ist erlaubt, globaler nicht.
HTTP-Aufruferout.HasCaller() meldet, ob ein Aufrufer eines HTTP-Triggers wartet; out.Respond(resp) antwortet ihm – die erste Antwort gilt. Beispiel internal/transforms/http/response.go.
ConnectionsEin Feld mit schema:"connection=sqlite" nennt eine Connection; out.Connection(ctx, name) liefert sie mit aufgelösten Variablen und Secrets (nie ausgeben). SQL-Felder mit format=runnel-sql kommen unverändert an, Werte als @name mit params. Beispiel internal/transforms/db/tableinput.go.
Aufrufender Workflowout.Rows() liefert die Datensätze, die ein Workflow mitgegeben hat (rows an core.run-pipeline); out.AddResult(r) gibt einen zurück (output.rows).
LeistungWas je Record läuft, zählt bei Millionen Records. Neue Records mit bekannter Feldzahl mit record.Make(n) anlegen; feste, eindeutige Namen sammeln und mit record.FromFields übernehmen; r.GetAt(i, name) liest zuerst an Position i. Nachschlagen einmal vor der Schleife, nicht je Record.
KopienMit Parallel: true darf der Transform mit copies: n laufen: n Objekte teilen sich die Eingabe. Nur setzen, wenn jeder Record für sich verarbeitet wird – nicht bei Ein- und Ausgaben.
Felder ermittelnEin Eingabe-Transform, dessen Felder aus der Eingabe kommen, setzt DetectFields: je Feld Name, Typvorschlag über format.Propose, die ersten Werte und eine Begründung. Der Editor zeigt dann „Detect fields…“. Tests mit Beispieldateien und ein Fuzz…-Ziel wie bei csv.input.

3. Schema (Init)

Beispiel
// Init meldet das Schema der ausgegebenen Records und die gelesenen Felder (ADR 0007).
func (t *upper) Init(ic *transform.InitContext) (record.Schema, error) {
	ic.Use(t.Field, "field")            // Pfad innerhalb von with: – für Datei, Zeile, Spalte
	return ic.In.With(t.Field, record.String), nil
}
  • ic.In ist das Schema der eingehenden Records – bei mehreren Links gemischt, leer und geschlossen ohne Eingang.
  • Jedes Feld, das der Transform liest, mit ic.Use melden: fehlt es im geschlossenen Schema, ist es ein Fehler, im offenen eine Warnung – jeweils mit „did you mean …?“.
  • Das Ergebnis beschreibt die Ausgabe: geschlossen, wenn alle Felder bekannt sind (z. B. Eingaben mit Felddefinition), offen, wenn weitere vorkommen können. Transforms, die nur weiterreichen, geben ic.In zurück.
  • Ohne Init gilt die Ausgabe als offen und unbekannt – für neue Transforms nur, wenn sich wirklich nichts ableiten lässt.
  • Ausdrücke je Datensatz mit transform.CompileExpression in New übersetzen, die Felder aus expr.Fields() mit ic.Use melden und in Process mit expr.Bool(out, r) auswerten. Ein Expression gehört genau einem Transform-Objekt.
  • Konstante Werte aus der Konfiguration mit record.Normalize umwandeln – transform.DecodeConfig liefert Zahlen als json.Number.

4. Tests

Beispiel
func TestUpper(t *testing.T) {
	tr := transformtest.New(t, upperDefinition, map[string]any{"field": "name"})
	out, logs, err := transformtest.Run(context.Background(), tr, record.New(record.Field{Name: "name", Value: "ada"}))
	…
}
  • transformtest.Run gibt Records in einen Transform und liefert die ausgegebenen Records, Log und Fehler. Dazu RunRouted (Ziele), RunWithErrorLink (Fehler-Link) und RunWithValues (Werte des Laufs).
  • Vertragstest (internal/transforms/transforms_test.go) läuft für jeden Transform: Kategorie, Texte, Beschreibungen aller Felder, unbekannte Felder werden abgelehnt, Beispielkonfiguration aus dem Schema wird angenommen, Abbruch.
  • Zusammenspiel mehrerer Transforms über die Engine: Tests in internal/engine/pipeline, Beispiele unter examples/.
  • Golden-Dateien des Katalogs mit go test ./internal/cli -update neu erzeugen und den Diff prüfen.

5. Checkliste für den PR

  • Eine Datei je Transform, Eintrag in register.go, Kategorie, Label, Beschreibung, doc für jedes Feld
  • Feldnamen mit format=runnel-field, Link-Ziele mit format=runnel-target; ein Example
  • Werte mit Variablen werden in Process geprüft; Emit-Fehler werden zurückgegeben
  • Init meldet das Ausgabeschema und alle gelesenen Felder (ic.Use), mit Tests
  • Tests mit transformtest, Vertragstest grün, Katalog-Goldens geprüft
  • Konzept Kap. 12.2 und Roadmap aktualisiert, ggf. Beispiel unter examples/

Vorlage: core.filter

Ein vollständiger Transform aus dem Repository mit Ausdruck je Datensatz, Feldmeldung in Init, Fehler-Link über out.Fail, Kopien (Parallel) und einer Log-Zeile am Ende.

internal/transforms/core/filter.go
package core

import (
	"context"
	"fmt"
	"log/slog"

	"github.com/runnelhq/runnel/internal/record"
	"github.com/runnelhq/runnel/internal/transform"
)

// core.filter passes on the records for which a condition is true.
var filterDefinition = transform.Definition{
	Parallel:     true,
	Type:         "core.filter",
	RecordErrors: true,
	Category:     transform.CategoryTransform,
	Label:        "Filter",
	Description:  "Passes on the records for which a condition is true",
	Example:      "condition: \"{{ record.umsatz > 0 && record.ort != '' }}\"\n",
	Config:       filter{},
	New:          newFilter,
}

type filter struct {
	Condition string `json:"condition" doc:"Expression that must be true for a record to pass, e.g. {{ record.amount > 0 }}; a comparison with an empty value is false" schema:"required,example={{ record.amount > 0 }}"`

	cond *transform.Expression
}

func newFilter(with map[string]any) (transform.Transform, error) {
	t := &filter{}
	if err := transform.DecodeConfig(with, t); err != nil {
		return nil, err
	}
	cond, err := transform.CompileExpression(t.Condition)
	if err != nil {
		return nil, fmt.Errorf("condition: %w", err)
	}
	t.cond = cond
	return t, nil
}

// Init checks the fields of the condition and passes the schema on: the records stay as
// they are.
func (t *filter) Init(ic *transform.InitContext) (record.Schema, error) {
	for _, f := range t.cond.Fields() {
		ic.Use(f, "condition")
	}
	return ic.In, nil
}

func (t *filter) Process(ctx context.Context, in <-chan transform.Batch, out *transform.Output) error {
	var read, kept, failed int64
	for b := range in {
		for _, r := range b {
			read++
			ok, err := t.cond.Bool(out, r)
			if err != nil {
				// To an error link, or the pipeline stops.
				failed++
				if err := out.Fail(r, "", fmt.Errorf("record %d: %w", read, err)); err != nil {
					return err
				}
				continue
			}
			if !ok {
				continue
			}
			kept++
			if err := out.Emit(r); err != nil {
				return err
			}
		}
	}
	if err := ctx.Err(); err != nil {
		return err
	}
	if failed > 0 {
		out.Logf(slog.LevelInfo, "kept %d of %d records, dropped %d, %d with errors", kept, read, read-kept-failed, failed)
	} else {
		out.Logf(slog.LevelInfo, "kept %d of %d records, dropped %d", kept, read, read-kept)
	}
	return nil
}

Developer docs · Components

Developing a new transform

Transforms are the building blocks of pipelines: they read records, change, filter or write them – as a stream, with constant memory even for millions of rows.

Source (German): docs/dev/TRANSFORMS.md · Background: ADR 0007 (type system), ADR 0013 (namespaces).

Extends the action guide

Namespaces, configuration (with:), schema tags, texts, Windows specifics and documentation work as in Developing actions. This page only covers what is different for transforms.

Examples in the repository: internal/transforms/core/ – generate.go (input without incoming links), dummy.go (passes records on), log.go (configuration, log); internal/transforms/csv/ – reading and writing files with positions in errors, a temporary file and encodings.

1. Layout

Layout
internal/transforms/<namespace>/
  register.go          # one line per transform
  <name>.go            # the transform
  <name>_test.go       # its tests
  • Separate registry from actions: the same type name may exist as an action and as a transform (e.g. core.log). A new namespace is added in internal/transforms/transforms.go.
  • Category (transform.Category…): input, transform, flow, execution, combine, output.
  • Configuration as for actions with transform.DecodeConfig and the doc and schema tags. Fields that may contain ${…} are declared as string – numbers such as rows too. The value is checked in Process, not in New: runnel validate calls New with the variables as written in the file.
  • For the editor: names of existing fields of incoming records with schema:"format=runnel-field" (also on lists such as groupBy), targets of data links with format=runnel-target, properties that only apply to some values of another one with only=<field>:<a>|<b>. Names of new fields get no format.
  • Every transform with a configuration gets an Example (the with: values in YAML) for the help in the panel; the contract test checks that New accepts it.

2. Processing (Process)

Example: upper-case text
func (t *upper) Process(ctx context.Context, in <-chan transform.Batch, out *transform.Output) error {
	for b := range in {                 // until all incoming links have ended
		for _, r := range b {
			v, _ := r.Get(t.Field)
			r.Set(t.Field, strings.ToUpper(fmt.Sprint(v)))
			if err := out.Emit(r); err != nil {
				return err              // pipeline cancelled
			}
		}
	}
	return nil
}
TopicRule
Inputin delivers batches until all incoming links have ended; mixed for several links. A transform without incoming links (input) gets a closed channel and creates records itself.
Outputout.Emit(r) per record; the engine bundles batches and passes every record to all outgoing links (copies from the second on). Don't change a record after Emit. out.EmitTo(id, r) sends it only to the data link to a specific transform (example switch.go).
BackpressureEmit blocks while the following transforms are busy – don't buffer yourself, or memory grows.
CancellationEmit returns an error on cancellation: return it immediately. For long steps without Emit (e.g. opening a file) pass ctx on.
ErrorsAn error returned by Process stops the whole pipeline. If a single record can't be processed, call out.Fail(r, field, err): with an error link the record goes there (with _error, _errorField, _errorTransform), otherwise Fail returns the error. Set RecordErrors: true in the definition; out.HasErrorLinks() tells whether there is an error link.
Early endA transform may stop before in is empty; the engine discards the rest.
RecordsOrdered fields (internal/record): Get, Set, Delete, Clone; names starting with _ are reserved for metadata. Values as string, int64, decimal.Decimal, float64, bool, record.Date, time.Time, []byte, map[string]any/[]any; convert foreign values with record.Normalize.
Logout.Logf: Info for results, Debug for details; never Info per record for large data.
StateA transform object runs in exactly one goroutine; state in the object is fine, global state is not.
HTTP callersout.HasCaller() reports whether a caller of an HTTP trigger is waiting; out.Respond(resp) answers it – the first response wins. Example internal/transforms/http/response.go.
ConnectionsA field with schema:"connection=sqlite" names a connection; out.Connection(ctx, name) returns it with variables and secrets resolved (never print them). SQL fields with format=runnel-sql arrive unchanged, values as @name with params. Example internal/transforms/db/tableinput.go.
Calling workflowout.Rows() returns the records a workflow passed in (rows on core.run-pipeline); out.AddResult(r) returns one (output.rows).
PerformanceWhatever runs per record counts with millions of records. Create records with a known field count with record.Make(n); collect fixed, unique names and take them over with record.FromFields; r.GetAt(i, name) reads position i first. Look things up once before the loop, not per record.
CopiesWith Parallel: true the transform may run with copies: n: n objects share the input. Only set it when every record is processed on its own – not for inputs and outputs.
Detect fieldsAn input transform whose fields come from its input sets DetectFields: per field the name, a type proposal via format.Propose, the first values and a reason. The editor then shows “Detect fields…”. Tests with sample files and a Fuzz… target as for csv.input.

3. Schema (Init)

Example
// Init reports the schema of the emitted records and the fields it reads (ADR 0007).
func (t *upper) Init(ic *transform.InitContext) (record.Schema, error) {
	ic.Use(t.Field, "field")            // path within with: – for file, line, column
	return ic.In.With(t.Field, record.String), nil
}
  • ic.In is the schema of the incoming records – mixed for several links, empty and closed without input.
  • Report every field the transform reads with ic.Use: if it's missing in a closed schema that is an error, in an open one a warning – each with “did you mean …?”.
  • The result describes the output: closed when all fields are known (e.g. inputs with a field definition), open when others may occur. Transforms that only pass records on return ic.In.
  • Without Init the output counts as open and unknown – for new transforms only when nothing can really be derived.
  • Compile per-record expressions with transform.CompileExpression in New, report the fields from expr.Fields() with ic.Use and evaluate them in Process with expr.Bool(out, r). An Expression belongs to exactly one transform object.
  • Convert constant values from the configuration with record.Normalize – transform.DecodeConfig returns numbers as json.Number.

4. Tests

Example
func TestUpper(t *testing.T) {
	tr := transformtest.New(t, upperDefinition, map[string]any{"field": "name"})
	out, logs, err := transformtest.Run(context.Background(), tr, record.New(record.Field{Name: "name", Value: "ada"}))
	…
}
  • transformtest.Run feeds records into a transform and returns the emitted records, log and error. Also RunRouted (targets), RunWithErrorLink (error link) and RunWithValues (run values).
  • The contract test (internal/transforms/transforms_test.go) runs for every transform: category, texts, descriptions of all fields, rejection of unknown fields, acceptance of a sample configuration from the schema, cancellation.
  • Interplay of several transforms through the engine: tests in internal/engine/pipeline, examples under examples/.
  • Regenerate the catalog golden files with go test ./internal/cli -update and review the diff.

5. Pull request checklist

  • One file per transform, entry in register.go, category, label, description, doc for every field
  • Field names with format=runnel-field, link targets with format=runnel-target; an Example
  • Values with variables are checked in Process; Emit errors are returned
  • Init reports the output schema and every field read (ic.Use), with tests
  • Tests with transformtest, contract test green, catalog goldens reviewed
  • Concept ch. 12.2 and roadmap updated, example under examples/ if useful

Template: core.filter

A complete transform from the repository with a per-record expression, field reporting in Init, an error link via out.Fail, copies (Parallel) and a log line at the end.
