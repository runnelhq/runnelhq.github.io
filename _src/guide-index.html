Handbuch

Runnel benutzen

Dieses Handbuch richtet sich an alle, die Runnel installieren, Workflows und Pipelines bauen und betreiben. Es beschreibt den Stand der Vorabversion – einige Funktionen kommen erst noch, sie sind entsprechend markiert.

Stand: Runnel v0.1.0-alpha.13 vom 27.11.2026; Plugins nach sdk-go v0.3.0, plugin-iban v0.3.0 und plugin-ldap v0.1.0. Grundlage sind README, Konzept und die Beispiele unter examples/. Die Referenzen zu Bausteinen und Ausdrücken sind direkt aus dem Programm erzeugt.

Vorabversion

Runnel ist ein Vibe-Coding-Projekt in Entwicklung. Formate und Befehle können sich bis Version 1.0 noch ändern. Vor produktivem Einsatz bitte selbst prüfen.

Begriffe

Projekt
Ein Ordner mit project.yaml und allen Dateien, die zusammengehören. Er lässt sich mit Git versionieren und als Ganzes kopieren.
Workflow
Steuert einen Ablauf: Actions nacheinander oder parallel, verbunden durch Links mit Bedingung (Erfolg, Fehler, immer, Ausdruck). Datei *.workflow.yaml.
Pipeline
Bewegt Daten: Transforms lesen, ändern und schreiben Datensätze als Strom. Datei *.pipeline.yaml.
Action, Transform
Die Bausteine – z. B. file.copy, http.request, csv.input. Die vollständige Liste steht in der Referenz.
Environment
Eine Umgebung wie dev oder prod mit eigenen Variablen, z. B. Pfaden und Servernamen. Datei environments/<name>.yaml.
Variable, Parameter
${NAME} setzt Werte aus Projekt, Environment oder Startparametern ein. Parameter sind die Eingaben eines Workflows oder einer Pipeline.
Ausdruck
{{ … }} berechnet Werte zur Laufzeit, z. B. ein Datum oder eine Bedingung. Siehe Ausdrücke.
Connection
Zugang zu einer Datenbank, einer HTTP-API oder einem Mailserver, abgelegt unter connections/. Passwörter stehen dort als ${secret:…}.
Trigger
Startet Workflows oder Pipelines automatisch: nach Zeitplan, im Intervall, bei neuen Dateien oder per HTTP. Datei unter triggers/.
Plugin
Ein eigenes Programm unter plugins/<name>/, das weitere Actions, Transforms oder Connection-Typen anbietet, z. B. für LDAP. Läuft erst nach Freigabe auf dem Rechner. Siehe Plugins.
Run-Historie
Alle beendeten Läufe mit Status und Log, je Projekt in einer Datei im Datenordner. Siehe Betrieb.

Aufbau eines Projekts

D:\flows\
  project.yaml                 # Name, Standard-Environment, gemeinsame Variablen
  environments\
    dev.yaml                   # Variablen je Umgebung
    prod.yaml
  connections\
    erp.yaml                   # Datenbank-Zugang
  triggers\
    nightly.yaml               # Zeitplan, Intervall, Ordner oder HTTP
  plugins\
    ldap\                      # Plugin mit plugin.yaml und Programm
  workflows\
    import.workflow.yaml
  pipelines\
    customers.pipeline.yaml

Die Ordnernamen workflows und pipelines sind eine Empfehlung; Runnel erkennt Dateien an ihrer Endung. Fest sind environments/, connections/, triggers/ und plugins/. Relative Pfade in allen Dateien beziehen sich auf den Projektordner – nie auf das Verzeichnis, aus dem Runnel gestartet wurde.

Erste Schritte

  1. Herunterladen und entpacken – siehe Installation.
  2. Projekt anlegen: runnel init D:\flows legt project.yaml, die Ordner, ein Environment dev, einen kleinen Beispiel-Workflow und eine .gitignore an. Ohne Terminal geht es auch im Editor: runnel serve in einem leeren Ordner starten, dann „Create project“.
  3. Prüfen: runnel validate D:\flows – meldet Fehler mit Datei, Zeile und Spalte.
  4. Ausführen: runnel run D:\flows\workflows\hello.workflow.yaml
  5. Im Editor öffnen: runnel serve D:\flows, dann http://127.0.0.1:7300 im Browser.
runnel init D:\flows
runnel run D:\flows\workflows\hello.workflow.yaml
08:36:50.489 INFO  workflow "hello" started (environment dev), run 01M8E2CVNJGXKVM005PBYA30TK
08:36:50.490 INFO  [greet] Hello, World! (development)
08:36:50.490 INFO  workflow "hello" succeeded in 0s

Mehr Beispiele stehen im Repository unter examples/ (als ZIP über Code → Download ZIP), fertige Anbindungen im Kochbuch.

User guide

Using Runnel

This guide is for everyone who installs Runnel, builds workflows and pipelines and runs them. It describes the pre-release – some features are still to come and are marked as such.

As of Runnel v0.1.0-alpha.13 on 2026-11-27; plugins as of sdk-go v0.3.0, plugin-iban v0.3.0 and plugin-ldap v0.1.0. Based on the README, the concept (German) and the examples under examples/. The component and expression references are generated directly from the program.

Pre-release

Runnel is a vibe coding project under development. Formats and commands may still change before version 1.0. Please check it yourself before using it in production.

Concepts

Project
A folder with project.yaml and all files that belong together. It can be versioned with Git and copied as a whole.
Workflow
Controls a process: actions in sequence or in parallel, connected by links with a condition (success, failure, always, expression). File *.workflow.yaml.
Pipeline
Moves data: transforms read, change and write records as a stream. File *.pipeline.yaml.
Action, transform
The components – e.g. file.copy, http.request, csv.input. The full list is in the reference.
Environment
An environment such as dev or prod with its own variables, e.g. paths and server names. File environments/<name>.yaml.
Variable, parameter
${NAME} inserts values from the project, the environment or start parameters. Parameters are the inputs of a workflow or pipeline.
Expression
{{ … }} computes values at run time, e.g. a date or a condition. See Expressions.
Connection
Access to a database, an HTTP API or a mail server, stored under connections/. Passwords appear there as ${secret:…}.
Trigger
Starts workflows or pipelines automatically: on a schedule, at intervals, for new files or via HTTP. File under triggers/.
Plugin
A program of its own under plugins/<name>/ that offers more actions, transforms or connection types, e.g. for LDAP. Runs only once trusted on the machine. See Plugins.
Run history
All finished runs with status and log, one file per project in the data folder. See Operation.

Project layout

D:\flows\
  project.yaml                 # name, default environment, shared variables
  environments\
    dev.yaml                   # variables per environment
    prod.yaml
  connections\
    erp.yaml                   # database access
  triggers\
    nightly.yaml               # schedule, interval, folder or HTTP
  plugins\
    ldap\                      # plugin with plugin.yaml and program
  workflows\
    import.workflow.yaml
  pipelines\
    customers.pipeline.yaml

The folder names workflows and pipelines are a recommendation; Runnel recognizes files by their extension. environments/, connections/, triggers/ and plugins/ are fixed. Relative paths in all files refer to the project folder – never to the directory Runnel was started from.

First steps

  1. Download and unpack – see Installation.
  2. Create a project: runnel init D:\flows creates project.yaml, the folders, an environment dev, a small example workflow and a .gitignore. It also works without a terminal in the editor: start runnel serve in an empty folder, then “Create project”.
  3. Validate: runnel validate D:\flows – reports errors with file, line and column.
  4. Run: runnel run D:\flows\workflows\hello.workflow.yaml
  5. Open in the editor: runnel serve D:\flows, then http://127.0.0.1:7300 in the browser.
runnel init D:\flows
runnel run D:\flows\workflows\hello.workflow.yaml
08:36:50.489 INFO  workflow "hello" started (environment dev), run 01M8E2CVNJGXKVM005PBYA30TK
08:36:50.490 INFO  [greet] Hello, World! (development)
08:36:50.490 INFO  workflow "hello" succeeded in 0s

More examples are in the repository under examples/ (as a ZIP via Code → Download ZIP), ready-made integrations in the cookbook.
