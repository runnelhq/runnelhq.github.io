IBANs prüfen (Plugin)

Prüft die IBANs einer CSV-Datei mit dem Plugin iban: gültige gehen in einheitlicher Schreibweise mit Land und Bankleitzahl weiter, ungültige mit dem Grund in eine eigene Datei. Dazu bildet eine Action eine IBAN aus Bankleitzahl und Kontonummer.

Die Beispieldatei enthält drei gültige IBANs (DE, AT, IT) und zwei ungültige: eine mit falscher Prüfziffer und eine mit einer Stelle zu wenig. Sie landen mit _error („the check digits are wrong …“, „an IBAN of DE has 22 characters, not 21“) in out/accounts-rejected.csv. Geprüft werden Land, Länge, Aufbau und Prüfziffern – nicht, ob Bank oder Konto existieren.

Ausführen

Im Ordner des Rezepts (PowerShell):

Expand-Archive .\runnel-plugin-iban_<version>_windows_amd64.zip -DestinationPath .\plugins
runnel plugins trust . --plugin iban
runnel run workflows/check.workflow.yaml

Anpassen

  • format bestimmt die Schreibweise gültiger IBANs: electronic (ohne Leerzeichen), print (Vierergruppen) oder keep. countryField, bankCodeField und branchCodeField legen neue Felder an; leer lassen, wenn sie nicht gebraucht werden.
  • Statt auf den Fehler-Link kann invalid: <id> ungültige Datensätze unverändert an einen anderen Transform geben, z. B. für eine Liste zur Nachbearbeitung. allowEmpty: true lässt leere IBANs durch.
  • Für einzelne Werte im Workflow, etwa aus einem HTTP-Trigger: Action iban.validate mit iban: ${IBAN}; mit failOnInvalid: true scheitert sie bei einer ungültigen IBAN.

Validating IBANs (plugin)

Checks the IBANs of a CSV file with the iban plugin: valid ones go on in a uniform notation with country and bank code, invalid ones with the reason into a separate file. An action also builds an IBAN from bank code and account number.

Plugin
runnelhq/plugin-iban: transform and action iban.validate, action iban.create; computes locally only
Sign-in
none – nothing is sent
Status
Checked on 2026-11-26 with the releases Runnel v0.1.0-alpha.12 and plugin-iban 0.3.0: runnel validate and run completely with the recipe's sample data.

Prerequisites

NameKindMeaning
plugins/ibanPluginUnpack the archive from the releases into plugins/ and trust it with runnel plugins trust – see Installing plugins

Files

{{snippet:../kochbuch/iban/project.yaml|project.yaml}} {{snippet:../kochbuch/iban/data/accounts.csv|data/accounts.csv}} {{snippet:../kochbuch/iban/pipelines/accounts.pipeline.yaml|pipelines/accounts.pipeline.yaml}} {{snippet:../kochbuch/iban/workflows/check.workflow.yaml|workflows/check.workflow.yaml}}

The sample file has three valid IBANs (DE, AT, IT) and two invalid ones: one with a wrong check digit and one with a digit missing. They end up in out/accounts-rejected.csv with _error (“the check digits are wrong …”, “an IBAN of DE has 22 characters, not 21”). Country, length, structure and check digits are checked – not whether bank or account exist.

Running

In the recipe folder (PowerShell):

Expand-Archive .\runnel-plugin-iban_<version>_windows_amd64.zip -DestinationPath .\plugins
runnel plugins trust . --plugin iban
runnel run workflows/check.workflow.yaml

Adapting

  • format sets the notation of valid IBANs: electronic (no spaces), print (groups of four) or keep. countryField, bankCodeField and branchCodeField add new fields; leave them empty if not needed.
  • Instead of the error link, invalid: <id> passes invalid records unchanged to another transform, e.g. for a list to fix by hand. allowEmpty: true lets empty IBANs through.
  • For single values in a workflow, e.g. from an HTTP trigger: action iban.validate with iban: ${IBAN}; with failOnInvalid: true it fails for an invalid IBAN.
