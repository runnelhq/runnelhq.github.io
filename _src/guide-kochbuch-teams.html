Microsoft Teams

Schickt eine Nachricht als Karte in einen Teams-Kanal – über einen Workflow-Webhook. Der Workflow notify dient als Connector: Andere Workflows rufen ihn auf, z. B. auf einem Fehler-Link.

API
Microsoft Teams, Workflows-App: Vorlage „Post to a channel when a webhook request is received“
Anmeldung
Signatur sig in der Adresse, als apiKey in der Query
Stand
Runnel-seitig geprüft am 27.11.2026 mit Runnel v0.1.0-alpha.13: runnel validate und Ausführung gegen einen Testserver, der die API nachbildet. Gegen die echte API noch nicht ausgeführt – Endpunkte und Felder nach der Dokumentation des Anbieters (Stand 11/2026).

Voraussetzungen

NameArtBedeutung
TEAMS_URLVariableAdresse des Webhooks aus Teams ohne den Teil &sig=…
TEAMS_SIGSecretWert von sig aus der Adresse – als Umgebungsvariable

Secrets kommen hier aus Umgebungsvariablen (secretStore: env in project.yaml); für den Dienst die Variable beim Dienstkonto setzen. Ohne diese Zeile liest Runnel sie aus dem lokalen Secret-Store: runnel secret set NAME.

Die Action nennt die vollständige Adresse (url: ${TEAMS_URL}), weil die Query der Webhook-Adresse erhalten bleiben muss; die Connection hängt die Signatur an. Ein Aufruf aus einem anderen Workflow steht in notify-on-failure.workflow.yaml.

Ausführen

Im Ordner des Rezepts (PowerShell):

$env:TEAMS_SIG = "…"
runnel run --param TITLE="Import done" --param TEXT="1.234 rows" workflows/notify.workflow.yaml

Anpassen

  • In Teams am Kanal „Workflows“ wählen, die Vorlage für Webhooks anlegen und die angezeigte Adresse kopieren. Alles bis vor &sig= wird TEAMS_URL, der Wert danach TEAMS_SIG.
  • Die Karte ist eine Adaptive Card; weitere Elemente unter content.body ergänzen. Eine Nachricht darf höchstens 28 KB groß sein.
  • Die Signatur ist ein Zugangsdatum: Wer die vollständige Adresse kennt, kann in den Kanal schreiben. Deshalb steht sie als Secret in der Connection und nicht im Workflow.

User guide · Cookbook

Microsoft Teams

Posts a message as a card to a Teams channel – through a workflow webhook. The notify workflow acts as a connector: other workflows call it, e.g. on a failure link.

API
Microsoft Teams, Workflows app: template “Post to a channel when a webhook request is received”
Sign-in
Signature sig in the address, as apiKey in the query
Status
Checked on the Runnel side on 2026-11-27 with Runnel v0.1.0-alpha.13: runnel validate and runs against a test server that mimics the API. Not yet run against the real API – endpoints and fields per the provider's documentation (as of 11/2026).

Prerequisites

NameKindMeaning
TEAMS_URLVariableWebhook address from Teams without the part &sig=…
TEAMS_SIGSecretValue of sig from the address – as an environment variable

Secrets come from environment variables here (secretStore: env in project.yaml); for the service, set the variable for the service account. Without this line Runnel reads them from the local secret store: runnel secret set NAME.

Files

{{snippet:../kochbuch/teams/project.yaml|project.yaml}} {{snippet:../kochbuch/teams/connections/teams.yaml|connections/teams.yaml}} {{snippet:../kochbuch/teams/workflows/notify.workflow.yaml|workflows/notify.workflow.yaml}} {{snippet:../kochbuch/teams/workflows/notify-on-failure.workflow.yaml|workflows/notify-on-failure.workflow.yaml}}

The action names the full address (url: ${TEAMS_URL}) because the query of the webhook address must be kept; the connection adds the signature. A call from another workflow is in notify-on-failure.workflow.yaml.

Running

In the recipe folder (PowerShell):

$env:TEAMS_SIG = "…"
runnel run --param TITLE="Import done" --param TEXT="1.234 rows" workflows/notify.workflow.yaml

Adapting

  • In Teams, choose “Workflows” on the channel, create the webhook template and copy the address shown. Everything up to &sig= becomes TEAMS_URL, the value after it TEAMS_SIG.
  • The card is an Adaptive Card; add elements under content.body. A message may be at most 28 KB.
  • The signature is a credential: anyone with the full address can post to the channel. That is why it is a secret in the connection, not in the workflow.
