Active Directory (Plugin)

Exportiert die aktiven Benutzer einer Organisationseinheit seitenweise als CSV-Datei und listet die Mitglieder einer Gruppe – mit dem Plugin ldap und seinem Connection-Typ.

Plugin
runnelhq/plugin-ldap: Connection-Typ ldap, Transform ldap.input, Action ldap.search; auch für OpenLDAP
Anmeldung
Dienstkonto mit Lesezugriff, über LDAPS (TLS)
Stand
Geprüft am 27.11.2026 mit den Releases Runnel v0.1.0-alpha.13 und plugin-ldap 0.1.0: runnel validate; ausgeführt gegen OpenLDAP mit TLS und 1.200 Benutzern (Paging), dabei mit den Attributen von OpenLDAP statt sAMAccountName, memberOf und objectGUID. Gegen ein echtes Active Directory noch nicht ausgeführt.

Secrets kommen hier aus Umgebungsvariablen (secretStore: env in project.yaml); für den Dienst die Variable beim Dienstkonto setzen. Ohne diese Zeile liest Runnel sie aus dem lokalen Secret-Store: runnel secret set NAME.

Das Plugin liest mit pageSize seitenweise; so liefert Active Directory auch mehr als 1.000 Einträge, und im Speicher liegt immer nur etwa eine Seite. Mehrere Werte eines Attributs (memberOf) verbindet es im Textfeld mit ; , objectGUID kommt in der üblichen Schreibweise. Der Filter wählt nur aktive Konten: Bit 2 von userAccountControl (deaktiviert) ist nicht gesetzt.

Ausführen

Im Ordner des Rezepts (PowerShell):

$env:AD_PASSWORD = "…"
runnel run workflows/export.workflow.yaml
runnel run --param OU=OU=Sales,OU=Users workflows/export.workflow.yaml
runnel run --param GROUP=App-Users workflows/group-members.workflow.yaml

Anpassen

  • Im Editor zeigt die Connection die Felder des Plugins; „Test connection“ meldet sich nur an und liest die Version des Servers – geschrieben wird nichts. Vertraut der Rechner der CA des Domänencontrollers nicht, nennt caFile sie als PEM-Datei.
  • „Detect fields“ an ldap.input liest die ersten Einträge mit allen Attributen und schlägt Typen vor, z. B. datetime für lastLogonTimestamp und pwdLastSet. Ohne fields kommen dn und alle Attribute als Text.
  • Werte aus Parametern oder Variablen gehören immer in filterValues und werden dort für LDAP maskiert. Direkt in filter könnte ein Wert wie *)(cn=* die Suche ändern; im Rezept findet er schlicht keine Gruppe.

User guide · Cookbook

Active Directory (plugin)

Exports the active users of an organizational unit page by page as a CSV file and lists the members of a group – with the ldap plugin and its connection type.

Plugin
runnelhq/plugin-ldap: connection type ldap, transform ldap.input, action ldap.search; also for OpenLDAP
Sign-in
Service account with read access, via LDAPS (TLS)
Status
Checked on 2026-11-27 with the releases Runnel v0.1.0-alpha.13 and plugin-ldap 0.1.0: runnel validate; run against OpenLDAP with TLS and 1,200 users (paging), using OpenLDAP's attributes instead of sAMAccountName, memberOf and objectGUID. Not yet run against a real Active Directory.

Prerequisites

NameKindMeaning
plugins/ldapPluginUnpack the archive from the releases into plugins/ and trust it with runnel plugins trust
LDAP_URL, LDAP_USER, LDAP_BASEVariableDomain controller (ldaps://…), service account (user@domain) and search base
AD_PASSWORDSecretPassword of the service account – as an environment variable

Secrets come from environment variables here (secretStore: env in project.yaml); for the service, set the variable for the service account. Without this line Runnel reads them from the local secret store: runnel secret set NAME.

Files

{{snippet:../kochbuch/ldap/project.yaml|project.yaml}} {{snippet:../kochbuch/ldap/connections/ad.yaml|connections/ad.yaml}} {{snippet:../kochbuch/ldap/pipelines/users.pipeline.yaml|pipelines/users.pipeline.yaml}} {{snippet:../kochbuch/ldap/workflows/export.workflow.yaml|workflows/export.workflow.yaml}} {{snippet:../kochbuch/ldap/workflows/group-members.workflow.yaml|workflows/group-members.workflow.yaml}}

The plugin reads page by page with pageSize; this way Active Directory returns more than 1,000 entries too, and only about one page is in memory. Several values of an attribute (memberOf) are joined with ; in a text field, objectGUID comes in its usual notation. The filter selects active accounts only: bit 2 of userAccountControl (disabled) is not set.

Running

In the recipe folder (PowerShell):

$env:AD_PASSWORD = "…"
runnel run workflows/export.workflow.yaml
runnel run --param OU=OU=Sales,OU=Users workflows/export.workflow.yaml
runnel run --param GROUP=App-Users workflows/group-members.workflow.yaml

Adapting

  • In the editor the connection shows the plugin's fields; “Test connection” only signs in and reads the server version – nothing is written. If the computer does not trust the domain controller's CA, caFile names it as a PEM file.
  • “Detect fields” on ldap.input reads the first entries with all attributes and suggests types, e.g. datetime for lastLogonTimestamp and pwdLastSet. Without fields, dn and all attributes come as text.
  • Values from parameters or variables always belong in filterValues, where they are escaped for LDAP. Directly in filter, a value such as *)(cn=* could change the search; in the recipe it simply finds no group.
