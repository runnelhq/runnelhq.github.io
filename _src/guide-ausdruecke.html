Ausdrücke

Mit {{ … }} berechnet Runnel Werte zur Laufzeit: Daten, Texte, Bedingungen an Links oder Felder je Datensatz. Die Sprache ist expr, ergänzt um eine eigene Funktionsbibliothek.

Schreibweise

message: "Import vom {{ formatDate(addDays(today(), -1), 'dd.MM.yyyy') }}"
when: "{{ results.load.output.errors > 0 }}"
condition: "{{ record.umsatz > 0 && record.ort != '' }}"
value: "{{ upper(trim(record.name)) }}"
name: "{{ request?.body?.name ?? 'unknown' }}"
  • Steht im Feld nur der Ausdruck, behält das Ergebnis seinen Typ (Zahl, Datum, Liste). Steht Text drumherum, wird alles zu Text.
  • Texte in einfachen Anführungszeichen: 'abc'. Vergleiche ==, !=, <, >; logisch &&, ||, !.
  • ?. greift sicher auf Felder zu, die fehlen könnten; ?? liefert einen Ersatzwert für leere Werte.
  • Ein Vergleich mit einem leeren Wert ist falsch – isEmpty() und coalesce() helfen.
  • ${…} wird vorher eingesetzt und ist im Ausdruck Text. Für typisierte Parameter params.NAME verwenden.
  • Syntax und Namen prüft runnel validate schon vor dem Lauf; der Editor schlägt Namen und Funktionen beim Tippen vor.
  • Erlaubt sind nur die Funktionen der Referenz unten – weitere Funktionen von expr sind abgeschaltet, damit sich der Umfang nicht mit einem Update ändert. Ein anderer Aufruf ist ein Fehler mit Vorschlägen, z. B. unknown function "date" (similar: parseDate, formatDate, …). Operatoren wie in, matches, contains, startsWith, ??, ?: und | gehören zur Sprache und bleiben.
  • Listen mit Bedingung wie filter, map, any oder sortBy nehmen einen Ausdruck je Element: .feld bzw. # ist das Element, z. B. {{ count(results.files.output, .size > 0) }}.

In Pipelines steht der aktuelle Datensatz als record bereit, z. B. record.umsatz in core.filter oder core.calculate; dazu params und run.

User guide

Expressions

With {{ … }} Runnel computes values at run time: dates, texts, link conditions or fields per record. The language is expr, extended by Runnel's own function library.

Syntax

message: "Import of {{ formatDate(addDays(today(), -1), 'yyyy-MM-dd') }}"
when: "{{ results.load.output.errors > 0 }}"
condition: "{{ record.amount > 0 && record.city != '' }}"
value: "{{ upper(trim(record.name)) }}"
name: "{{ request?.body?.name ?? 'unknown' }}"
  • If the field holds only the expression, the result keeps its type (number, date, list). With text around it, everything becomes text.
  • Text in single quotes: 'abc'. Comparisons ==, !=, <, >; logical &&, ||, !.
  • ?. safely accesses fields that may be missing; ?? supplies a fallback for empty values.
  • A comparison with an empty value is false – isEmpty() and coalesce() help.
  • ${…} is substituted first and is text inside the expression. Use params.NAME for typed parameters.
  • runnel validate checks syntax and names before the run; the editor suggests names and functions while you type.
  • Only the functions of the reference below are allowed – other expr functions are switched off so the scope does not change with an update. Any other call is an error with suggestions, e.g. unknown function "date" (similar: parseDate, formatDate, …). Operators such as in, matches, contains, startsWith, ??, ?: and | are part of the language and stay.
  • Lists with a condition such as filter, map, any or sortBy take an expression per element: .field or # is the element, e.g. {{ count(results.files.output, .size > 0) }}.

In pipelines the current record is available as record, e.g. record.amount in core.filter or core.calculate; plus params and run.
