Server-API

Die API von runnel serve ist die einzige Schnittstelle des Editors zum Server – und ebenso für Skripte nutzbar. Außerhalb von /api/v1 liefert der Server den eingebetteten Editor aus.

Quelle: docs/dev/API.md (Stand v0.1.0-alpha.13) – mit allen Feldern und den Endpunkten zum Bearbeiten, Kopieren, Felder ermitteln und zur Datenvorschau. Grundlagen: ADR 0016 (Live-Ereignisse), ADR 0018 (HTTP-Trigger).

runnel serve examples/hello     # Projekt im Ordner oder darüber, Port 7300
runnel serve --port 0 .          # freier Port; die Ausgabe nennt die Adresse

Grundsätze

Adressenur 127.0.0.1; HTTP-Trigger haben einen eigenen Listener
Präfixalle Endpunkte unter /api/v1
FormatJSON (UTF-8, eingerückt); Dateiinhalte als Rohdaten
FehlerStatuscode und {"error": "…"} mit englischer, verständlicher Meldung; manche mit festem code, z. B. no_project
SchutzAnfragen müssen an localhost, 127.0.0.1 oder [::1] gerichtet sein (Schutz vor DNS-Rebinding); ein Origin-Header muss zum Server passen (Schutz vor fremden Webseiten). Sonst 403
Pfaderelativ zum Projektordner, Trenner /; versteckte Einträge, .., \, : und unter Windows reservierte Namen (CON, NUL …) werden mit 400 abgelehnt

Endpunkte

Öffentlich und intern (ADR 0029): Öffentliche Endpunkte – /version, /health, /catalog, /expressions und die Läufe unter /runs – ändern sich ab v1.0.0 nur additiv; Leser ignorieren unbekannte Schlüssel. Interne Endpunkte dienen dem eingebetteten Editor, der immer zur Version des Servers passt, und dürfen sich in jeder Version ändern – Skripte sollten sie nicht nutzen. „Öffentlich“ heißt zugesagt, nicht im Netz erreichbar: Für beide gelten dieselben Prüfungen von Host und Origin.

Konfliktschutz (ETag)

Jede Datei hat ein ETag (Hash des Inhalts). Gespeichert wird nur, wenn sich die Datei seit dem Laden nicht geändert hat – egal ob durch einen anderen Browser, einen Texteditor oder git pull.

AnfrageDatei existiertDatei fehlt
PUT ohne If-Match428 – ETag erforderlich201 – angelegt
PUT mit passendem If-Match200 – ersetzt–
PUT mit anderem If-Match412 – „changed in the meantime“412 – „deleted in the meantime“
DELETE ohne / mit passendem / mit anderem If-Match428 / 204 / 412428 / 412 / 412

If-Match: * überschreibt bewusst ohne Prüfung. Gespeichert wird atomar: temporäre Datei, dann Umbenennen.

Gestartet wird die gespeicherte Datei – Workflow oder Pipeline –, vorher wird sie wie bei runnel run geprüft. Statt path startet {"trigger": "triggers/nightly.yaml"} das Ziel einer gespeicherten Trigger-Datei mit deren Environment und Parametern („Run target now“).

AntwortBedeutung

status ist running, succeeded, failed oder cancelled; trigger nennt, was den Lauf gestartet hat (cron:<name>, interval:…, file:…, http:…). trigger ist zusätzlich cli für runnel run und editor für Läufe aus dem Editor oder mit POST /runs. GET /runs/{id} ergänzt den Status je Action und das Log (höchstens 5.000 Zeilen).

Run-Historie: GET /runs liefert laufende und kürzlich beendete Läufe aus dem Speicher und alle älteren aus der Run-Historie (SQLite-Datei je Projekt im Datenordner), neueste zuerst. Filter: status, path, trigger; Seiten mit before=<lauf-id> und limit (Standard 200, höchstens 1.000, sonst 400). GET /projects/current nennt unter history die Aufbewahrung (keepDays, maxRuns).

Ohne Projekt: Findet runnel serve keine project.yaml, startet der Server trotzdem. Bis ein Projekt angelegt ist, antworten nur /version, /health (degraded), /project und der Editor; alle übrigen Endpunkte antworten 409 mit {"code": "no_project"}.

Plugins

Für die Plugin-Verwaltung im Editor; dieselben Freigaben wie runnel plugins trust (Plugins entwickeln).

{ "plugins": [ {
    "name": "iban", "version": "0.2.0", "namespace": "iban",
    "folder": "plugins/iban", "program": "bin/iban.exe", "hash": "8b0d5e…41d2",
    "state": "trusted",
    "user": { "version": "0.2.0", "hash": "8b0d5e…41d2", "trusted": "2026-11-25T09:12:00Z", "current": true },
    "types": { "actions": [ … ], "transforms": [ … ], "connectionTypes": [ … ] },
    "uses": [ { "file": "pipelines/accounts.pipeline.yaml", "kind": "transform", "id": "check", "type": "iban.validate" } ] } ],
  "serviceApprovals": false, "canTrust": true }
  • state: trusted, not-trusted, changed (seit der Freigabe geändert) oder error (Grund in message). types nur bei trusted; uses liest Runnel aus den Dateien, ohne das Plugin zu starten.
  • POST /plugins/{name}/trust mit {"hash": "…"} gibt das Plugin für das Konto von runnel serve frei – nie für den Dienst. Der Hash muss dem Stand jetzt entsprechen: 409, wenn sich das Plugin seitdem geändert hat; 400 ohne Hash, 404 unbekannt, 403 im Windows-Dienst (canTrust: false).
  • …/untrust nimmt die Freigabe zurück, …/reload prüft und startet das Plugin erneut. Freigaben stehen im Server-Log.

HTTP-Trigger

HTTP-Trigger antworten nicht unter /api/v1, sondern auf einem eigenen Listener (--triggers, Standard 127.0.0.1:7301; im Netz per HTTPS) unter den Pfaden ihrer Trigger-Dateien.

Developer docs · Server

Server API

The API of runnel serve is the editor's only interface to the server – and just as usable from scripts. Outside /api/v1 the server delivers the embedded editor.

Source (German): docs/dev/API.md (as of v0.1.0-alpha.13) – with every field and the endpoints for editing, copying, field detection and data preview. Background: ADR 0016 (live events), ADR 0018 (HTTP triggers).

runnel serve examples/hello     # project in the folder or above, port 7300
runnel serve --port 0 .          # free port; the output names the address

Principles

Address127.0.0.1 only; HTTP triggers have their own listener
Prefixall endpoints under /api/v1
FormatJSON (UTF-8, indented); file contents as raw data
ErrorsStatus code and {"error": "…"} with an understandable English message; some with a fixed code, e.g. no_project
ProtectionRequests must target localhost, 127.0.0.1 or [::1] (DNS rebinding protection); an Origin header must match the server (protection against other web pages). Otherwise 403
Pathsrelative to the project folder, separator /; hidden entries, .., \, : and names reserved on Windows (CON, NUL …) are rejected with 400

Endpoints

Public and internal (ADR 0029, German): public endpoints – /version, /health, /catalog, /expressions and the runs under /runs – change only additively from v1.0.0; readers ignore unknown keys. Internal endpoints serve the embedded editor, which always matches the server's version, and may change in any version – scripts should not use them. “Public” means promised, not reachable on the network: the same host and origin checks apply to both.

Conflict protection (ETag)

Every file has an ETag (hash of its content). A save only succeeds if the file hasn't changed since it was loaded – whether by another browser, a text editor or git pull.

RequestFile existsFile missing
PUT without If-Match428 – ETag required201 – created
PUT with matching If-Match200 – replaced–
PUT with other If-Match412 – “changed in the meantime”412 – “deleted in the meantime”
DELETE without / matching / other If-Match428 / 204 / 412428 / 412 / 412

If-Match: * deliberately overwrites without a check. Saving is atomic: temporary file, then rename.

Runs

{{snippet:api-runs-en.sh|Start and follow a run}}

The saved file is started – workflow or pipeline – after the same checks as runnel run. Instead of path, {"trigger": "triggers/nightly.yaml"} starts the target of a saved trigger file with its environment and parameters (“Run target now”).

ResponseMeaning
201 + run, header LocationRun started; it keeps running in the background
422Errors in the workflow or project files (format as /validate)
400Unknown environment, parameters missing or of the wrong type
429Limit of concurrent runs reached (settings.maxConcurrentRuns)
404 / 503File not found / server shutting down
{{snippet:api-run.json|Run}}

status is running, succeeded, failed or cancelled; trigger names what started the run (cron:<name>, interval:…, file:…, http:…). trigger can also be cli for runnel run and editor for runs from the editor or via POST /runs. GET /runs/{id} adds the status per action and the log (at most 5,000 lines).

Run history: GET /runs returns running and recently finished runs from memory and all older ones from the run history (one SQLite file per project in the data folder), newest first. Filters: status, path, trigger; pages with before=<run id> and limit (default 200, at most 1,000, else 400). GET /projects/current names the retention under history (keepDays, maxRuns).

Plugins

For plugin management in the editor; the same approvals as runnel plugins trust (Developing plugins).

{ "plugins": [ {
    "name": "iban", "version": "0.2.0", "namespace": "iban",
    "folder": "plugins/iban", "program": "bin/iban.exe", "hash": "8b0d5e…41d2",
    "state": "trusted",
    "user": { "version": "0.2.0", "hash": "8b0d5e…41d2", "trusted": "2026-11-25T09:12:00Z", "current": true },
    "types": { "actions": [ … ], "transforms": [ … ], "connectionTypes": [ … ] },
    "uses": [ { "file": "pipelines/accounts.pipeline.yaml", "kind": "transform", "id": "check", "type": "iban.validate" } ] } ],
  "serviceApprovals": false, "canTrust": true }
  • state: trusted, not-trusted, changed (changed since trusted) or error (reason in message). types only when trusted; Runnel reads uses from the files without starting the plugin.
  • POST /plugins/{name}/trust with {"hash": "…"} trusts the plugin for the account of runnel serve – never for the service. The hash must match the current state: 409 if the plugin has changed since; 400 without a hash, 404 unknown, 403 in the Windows service (canTrust: false).
  • …/untrust withdraws the approval, …/reload checks and starts the plugin again. Approvals appear in the server log.

HTTP triggers

HTTP triggers do not answer under /api/v1 but on their own listener (--triggers, default 127.0.0.1:7301; HTTPS on the network) at the paths of their trigger files.

ResponseMeaning
202 + {"runId"}response: accepted: run started
Response of http.responseresponse: run: the run's first response; without http.response 200 with the outputs or 500
504response: run: no response within timeout; the run keeps going
400 / 401 / 403Parameter missing or invalid / token missing or wrong / request from a web page
404 / 405No trigger for the path / other method
413 / 415 / 429Body over 1 MiB / neither JSON nor form / concurrent run limit
