Installation

Runnel ist eine einzige ausführbare Datei. Es gibt kein Setup, keine Runtime und keine Datenbank: herunterladen, entpacken, starten.

Voraussetzungen

  • Windows 64 Bit (amd64) – das Hauptziel von Runnel – oder Linux 64 Bit (amd64).
  • Für den Editor ein aktueller Browser (Edge, Chrome, Firefox) auf demselben Rechner.
  • Schreibrechte im Projektordner für Ausgaben und – beim Windows-Dienst – Administratorrechte für die Einrichtung.

Herunterladen

Alle Versionen stehen unter github.com/runnelhq/runnel/releases. Bis Version 1.0 sind es Vorabversionen (z. B. v0.1.0-alpha.8).

DateiInhalt
runnel_<version>_windows_amd64.ziprunnel.exe, LICENSE, README.md, THIRD_PARTY_NOTICES.txt
runnel_<version>_linux_amd64.tar.gzrunnel und dieselben Begleitdateien
runnel_<version>_<os>_amd64.cdx.jsonSoftware-Stückliste (SBOM) im Format CycloneDX 1.6
SHA256SUMSPrüfsummen aller Dateien

Unter Windows einrichten

  1. ZIP in einen festen Ordner entpacken, z. B. C:\Tools\Runnel. Für den Windows-Dienst ist der Ordner wichtig: Der Dienst startet die exe, mit der er eingerichtet wurde.
  2. PowerShell im Ordner öffnen und die Version abfragen: .\runnel.exe version
  3. Optional den Ordner in den PATH aufnehmen, damit runnel überall aufrufbar ist.
Expand-Archive runnel_0.1.0-alpha.8_windows_amd64.zip -DestinationPath C:\Tools\Runnel
cd C:\Tools\Runnel
.\runnel.exe version

# Ordner dauerhaft in den PATH des Benutzers aufnehmen (neue Konsole öffnen)
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Tools\Runnel", "User")
SmartScreen-Warnung

Die runnel.exe ist noch nicht signiert; das Signieren ist vor Version 1.0 geplant. Beim ersten Start kann Windows deshalb warnen. Nach dem Prüfen der Herkunft (unten) lässt sich die Datei mit Unblock-File .\runnel.exe freigeben.

Unter Linux einrichten

tar -xzf runnel_0.1.0-alpha.8_linux_amd64.tar.gz
sudo install -m 755 runnel /usr/local/bin/runnel
runnel version

Unter Linux funktionieren CLI, Editor und Trigger wie unter Windows. Den Windows-Dienst gibt es dort nicht; für den Dauerbetrieb lässt sich runnel serve <projektordner> z. B. als systemd-Dienst starten.

Herkunft prüfen

Jedes Archiv hat eine Prüfsumme in SHA256SUMS und eine signierte Herkunftsbestätigung (SLSA Build Provenance), die belegt, dass es aus dem Repository von GitHub Actions gebaut wurde.

Get-FileHash .\runnel_0.1.0-alpha.8_windows_amd64.zip -Algorithm SHA256
# mit der Zeile in SHA256SUMS vergleichen

# Herkunft mit der GitHub CLI prüfen
gh attestation verify runnel_0.1.0-alpha.8_windows_amd64.zip --repo runnelhq/runnel

Aktualisieren

  1. Läuft Runnel als Dienst: runnel service stop (Konsole als Administrator).
  2. Die runnel.exe durch die neue Version ersetzen – am selben Ort.
  3. Projekte prüfen: runnel validate D:\flows. Bis Version 1.0 können sich Formate ändern; die Meldungen nennen Datei und Zeile.
  4. Dienst wieder starten: runnel service start.

Ein Befehl zum Aktualisieren (runnel update) und ein MSI-Installer sind geplant.

Entfernen

  • Dienst entfernen: runnel service uninstall (bei mehreren Diensten mit --name).
  • Den Ordner mit der runnel.exe löschen. Projekte liegen getrennt davon und bleiben erhalten.
  • Bei Bedarf auch Logs und Zertifikate: %ProgramData%\runnel\ (Dienst) und %LOCALAPPDATA%\runnel\.

User guide

Installation

Runnel is a single executable. There is no setup, no runtime and no database: download, unpack, start.

Requirements

  • Windows 64-bit (amd64) – Runnel's main target – or Linux 64-bit (amd64).
  • For the editor, a current browser (Edge, Chrome, Firefox) on the same machine.
  • Write access to the project folder for outputs and – for the Windows service – administrator rights for the setup.

Download

All versions are at github.com/runnelhq/runnel/releases. Until version 1.0 these are pre-releases (e.g. v0.1.0-alpha.8).

FileContents
runnel_<version>_windows_amd64.ziprunnel.exe, LICENSE, README.md, THIRD_PARTY_NOTICES.txt
runnel_<version>_linux_amd64.tar.gzrunnel and the same accompanying files
runnel_<version>_<os>_amd64.cdx.jsonSoftware bill of materials (SBOM) in CycloneDX 1.6 format
SHA256SUMSChecksums of all files

Setting up on Windows

  1. Unpack the ZIP into a permanent folder, e.g. C:\Tools\Runnel. The folder matters for the Windows service: the service starts the executable it was set up with.
  2. Open PowerShell in the folder and check the version: .\runnel.exe version
  3. Optionally add the folder to PATH so runnel works everywhere.
Expand-Archive runnel_0.1.0-alpha.8_windows_amd64.zip -DestinationPath C:\Tools\Runnel
cd C:\Tools\Runnel
.\runnel.exe version

# add the folder to the user's PATH permanently (open a new console)
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Tools\Runnel", "User")
SmartScreen warning

runnel.exe is not signed yet; signing is planned before version 1.0. Windows may therefore warn on first start. After verifying its origin (below), unblock the file with Unblock-File .\runnel.exe.

Setting up on Linux

tar -xzf runnel_0.1.0-alpha.8_linux_amd64.tar.gz
sudo install -m 755 runnel /usr/local/bin/runnel
runnel version

On Linux the CLI, editor and triggers work as on Windows. There is no Windows service; for continuous operation, start runnel serve <project folder> e.g. as a systemd service.

Verifying the origin

Every archive has a checksum in SHA256SUMS and a signed provenance attestation (SLSA build provenance) proving it was built from the repository by GitHub Actions.

Get-FileHash .\runnel_0.1.0-alpha.8_windows_amd64.zip -Algorithm SHA256
# compare with the line in SHA256SUMS

# verify the provenance with the GitHub CLI
gh attestation verify runnel_0.1.0-alpha.8_windows_amd64.zip --repo runnelhq/runnel

Updating

  1. If Runnel runs as a service: runnel service stop (console as administrator).
  2. Replace runnel.exe with the new version – in the same place.
  3. Check your projects: runnel validate D:\flows. Formats may change before version 1.0; messages name file and line.
  4. Start the service again: runnel service start.

An update command (runnel update) and an MSI installer are planned.

Removing

  • Remove the service: runnel service uninstall (with --name for several services).
  • Delete the folder with runnel.exe. Projects live separately and are kept.
  • If needed, also logs and certificates: %ProgramData%\runnel\ (service) and %LOCALAPPDATA%\runnel\.
