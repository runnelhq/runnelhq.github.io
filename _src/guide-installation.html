Installation

Runnel ist eine einzige ausführbare Datei. Es gibt kein Setup, keine Runtime und keine Datenbank: herunterladen, entpacken, starten.

Voraussetzungen

  • Windows 64 Bit (amd64) – das Hauptziel von Runnel – oder Linux 64 Bit (amd64).
  • Für den Editor ein aktueller Browser (Edge, Chrome, Firefox) auf demselben Rechner.
  • Schreibrechte im Projektordner für Ausgaben und – beim Windows-Dienst – Administratorrechte für die Einrichtung.

Herunterladen

Alle Versionen stehen unter github.com/runnelhq/runnel/releases. Bis Version 1.0 sind es Vorabversionen (z. B. v0.1.0-alpha.9).

DateiInhalt
runnel_<version>_windows_amd64.ziprunnel.exe, LICENSE, README.md, THIRD_PARTY_NOTICES.txt
runnel_<version>_linux_amd64.tar.gzrunnel und dieselben Begleitdateien
runnel_<version>_<os>_amd64.cdx.jsonSoftware-Stückliste (SBOM) im Format CycloneDX 1.6
SHA256SUMSPrüfsummen aller Dateien

Unter Windows einrichten

  1. ZIP in einen festen Ordner entpacken, z. B. C:\Tools\Runnel. Für den Windows-Dienst ist der Ordner wichtig: Der Dienst startet die exe, mit der er eingerichtet wurde.
  2. PowerShell im Ordner öffnen und die Version abfragen: .\runnel.exe version
  3. Optional den Ordner in den PATH aufnehmen, damit runnel überall aufrufbar ist.
Expand-Archive runnel_0.1.0-alpha.9_windows_amd64.zip -DestinationPath C:\Tools\Runnel
cd C:\Tools\Runnel
.\runnel.exe version

# Ordner dauerhaft in den PATH des Benutzers aufnehmen (neue Konsole öffnen)
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Tools\Runnel", "User")
SmartScreen-Warnung

Die runnel.exe ist noch nicht signiert; das Signieren ist vor Version 1.0 geplant. Beim ersten Start kann Windows deshalb warnen. Nach dem Prüfen der Herkunft (unten) lässt sich die Datei mit Unblock-File .\runnel.exe freigeben.

Unter Linux einrichten

tar -xzf runnel_0.1.0-alpha.9_linux_amd64.tar.gz
sudo install -m 755 runnel /usr/local/bin/runnel
runnel version

Unter Linux funktionieren CLI, Editor und Trigger wie unter Windows. Den Windows-Dienst gibt es dort nicht; für den Dauerbetrieb lässt sich runnel serve <projektordner> z. B. als systemd-Dienst starten.

Herkunft prüfen

Jedes Archiv hat eine Prüfsumme in SHA256SUMS und eine signierte Herkunftsbestätigung (SLSA Build Provenance), die belegt, dass es aus dem Repository von GitHub Actions gebaut wurde.

Get-FileHash .\runnel_0.1.0-alpha.9_windows_amd64.zip -Algorithm SHA256
# mit der Zeile in SHA256SUMS vergleichen

# Herkunft mit der GitHub CLI prüfen
gh attestation verify runnel_0.1.0-alpha.9_windows_amd64.zip --repo runnelhq/runnel

Aktualisieren

Ein Update tauscht nur die runnel.exe; der Editor steckt in ihr. Projektordner, Logs und Zertifikate bleiben, wo sie sind. Ein Befehl runnel update ist geplant, bis dahin geht es so:

  1. Laden und prüfen: ZIP der neuen Version und SHA256SUMS laden, Prüfsumme und Herkunft prüfen (siehe oben).
  2. Vorher testen: das ZIP in einen eigenen Ordner entpacken und das Projekt mit der neuen Version prüfen, während die alte noch läuft. Neue Meldungen zeigen, was vor dem Wechsel anzupassen ist – bis Version 1.0 nennen sie bei umbenannten Feldern auch den neuen Namen.
  3. Tauschen (Konsole als Administrator): Dienst stoppen, die alte Datei als runnel-old.exe behalten, die neue an dieselbe Stelle kopieren, Dienst starten. Welche Datei der Dienst startet, zeigt runnel service status unter Command.
  4. Kontrollieren: runnel version zeigt die neue Version, runnel service status den Zustand running; im Log beginnt der Start mit Starting runnel v…. Den Editor im Browser mit Strg+F5 neu laden.
.\runnel_0.2.0_windows_amd64\runnel.exe validate D:\flows
runnel service stop
Rename-Item C:\Tools\Runnel\runnel.exe runnel-old.exe
Copy-Item .\runnel_0.2.0_windows_amd64\runnel.exe C:\Tools\Runnel\runnel.exe
C:\Tools\Runnel\runnel.exe service start
C:\Tools\Runnel\runnel.exe version
  • Stopp: service stop wartet bis zu 30 s auf laufende Runs und bricht sie danach ab – am besten außerhalb der Zeitpläne wechseln.
  • Während des Wechsels entfallen Zeitpunkte von Zeitplan- und Intervall-Triggern; neue Dateien in überwachten Ordnern verarbeitet der Dienst nach dem Start; Aufrufe von HTTP-Triggern scheitern, bis er wieder läuft.
  • Läufe: Die Liste der Läufe liegt nur im Speicher und beginnt nach dem Neustart leer.
  • Mehrere Dienste, die dieselbe runnel.exe starten, vorher alle stoppen – Windows sperrt die Datei, solange einer läuft.
  • Ohne Dienst: runnel serve mit Strg+C beenden, Datei ersetzen, neu starten.
  • Zurück: Dienst stoppen, runnel-old.exe wieder in runnel.exe umbenennen, Dienst starten.
  • Anderer Ordner: Liegt die neue Version woanders, den Dienst mit ihr neu einrichten (service uninstall, dann service install mit denselben Optionen).

Entfernen

  • Dienst entfernen: runnel service uninstall (bei mehreren Diensten mit --name).
  • Den Ordner mit der runnel.exe löschen. Projekte liegen getrennt davon und bleiben erhalten.
  • Bei Bedarf auch Logs und Zertifikate: %ProgramData%\runnel\ (Dienst) und %LOCALAPPDATA%\runnel\.

User guide

Installation

Runnel is a single executable. There is no setup, no runtime and no database: download, unpack, start.

Requirements

  • Windows 64-bit (amd64) – Runnel's main target – or Linux 64-bit (amd64).
  • For the editor, a current browser (Edge, Chrome, Firefox) on the same machine.
  • Write access to the project folder for outputs and – for the Windows service – administrator rights for the setup.

Download

All versions are at github.com/runnelhq/runnel/releases. Until version 1.0 these are pre-releases (e.g. v0.1.0-alpha.9).

FileContents
runnel_<version>_windows_amd64.ziprunnel.exe, LICENSE, README.md, THIRD_PARTY_NOTICES.txt
runnel_<version>_linux_amd64.tar.gzrunnel and the same accompanying files
runnel_<version>_<os>_amd64.cdx.jsonSoftware bill of materials (SBOM) in CycloneDX 1.6 format
SHA256SUMSChecksums of all files

Setting up on Windows

  1. Unpack the ZIP into a permanent folder, e.g. C:\Tools\Runnel. The folder matters for the Windows service: the service starts the executable it was set up with.
  2. Open PowerShell in the folder and check the version: .\runnel.exe version
  3. Optionally add the folder to PATH so runnel works everywhere.
Expand-Archive runnel_0.1.0-alpha.9_windows_amd64.zip -DestinationPath C:\Tools\Runnel
cd C:\Tools\Runnel
.\runnel.exe version

# add the folder to the user's PATH permanently (open a new console)
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Tools\Runnel", "User")
SmartScreen warning

runnel.exe is not signed yet; signing is planned before version 1.0. Windows may therefore warn on first start. After verifying its origin (below), unblock the file with Unblock-File .\runnel.exe.

Setting up on Linux

tar -xzf runnel_0.1.0-alpha.9_linux_amd64.tar.gz
sudo install -m 755 runnel /usr/local/bin/runnel
runnel version

On Linux the CLI, editor and triggers work as on Windows. There is no Windows service; for continuous operation, start runnel serve <project folder> e.g. as a systemd service.

Verifying the origin

Every archive has a checksum in SHA256SUMS and a signed provenance attestation (SLSA build provenance) proving it was built from the repository by GitHub Actions.

Get-FileHash .\runnel_0.1.0-alpha.9_windows_amd64.zip -Algorithm SHA256
# compare with the line in SHA256SUMS

# verify the provenance with the GitHub CLI
gh attestation verify runnel_0.1.0-alpha.9_windows_amd64.zip --repo runnelhq/runnel

Updating

An update only replaces runnel.exe; the editor is inside it. Project folders, logs and certificates stay where they are. A runnel update command is planned; until then:

  1. Download and verify: get the new version's ZIP and SHA256SUMS, check checksum and origin (see above).
  2. Test first: unpack the ZIP into its own folder and validate the project with the new version while the old one keeps running. New messages show what to adapt before switching – until version 1.0 they also name the new name of renamed fields.
  3. Swap (console as administrator): stop the service, keep the old file as runnel-old.exe, copy the new one to the same place, start the service. runnel service status shows which file the service starts under Command.
  4. Check: runnel version shows the new version, runnel service status the state running; in the log the start begins with Starting runnel v…. Reload the editor in the browser with Ctrl+F5.
.\runnel_0.2.0_windows_amd64\runnel.exe validate D:\flows
runnel service stop
Rename-Item C:\Tools\Runnel\runnel.exe runnel-old.exe
Copy-Item .\runnel_0.2.0_windows_amd64\runnel.exe C:\Tools\Runnel\runnel.exe
C:\Tools\Runnel\runnel.exe service start
C:\Tools\Runnel\runnel.exe version
  • Stopping: service stop waits up to 30 s for running runs, then cancels them – best switch outside the schedules.
  • During the switch schedule and interval trigger times are skipped; new files in watched folders are processed after the start; calls to HTTP triggers fail until the service runs again.
  • Runs: the list of runs lives in memory only and starts empty after the restart.
  • Several services starting the same runnel.exe: stop them all first – Windows locks the file while one runs.
  • Without a service: end runnel serve with Ctrl+C, replace the file, start again.
  • Going back: stop the service, rename runnel-old.exe back to runnel.exe, start the service.
  • Other folder: if the new version lives elsewhere, set up the service again with it (service uninstall, then service install with the same options).

Removing

  • Remove the service: runnel service uninstall (with --name for several services).
  • Delete the folder with runnel.exe. Projects live separately and are kept.
  • If needed, also logs and certificates: %ProgramData%\runnel\ (service) and %LOCALAPPDATA%\runnel\.
