Den Editor entwickeln

Der Editor ist eine React-Anwendung in web/. Sie wird gebaut, in die runnel.exe eingebettet und von runnel serve unter http://127.0.0.1:7300/ ausgeliefert. Mit dem Server spricht sie nur über die Server-API.

Quelle: docs/dev/EDITOR.md – dort steht auch die vollständige Tabelle zum Verhalten jeder Funktion. Gestaltung: Corporate Design, freigegebene Mockups.

Voraussetzungen

  • Go in der Version aus go.mod
  • Node.js 22 LTS (web/.node-version) mit npm

Ohne Node baut make build-go eine exe ohne Editor; runnel serve zeigt dann unter / einen Hinweis. Die Go-Tests brauchen keinen Editor-Build.

Befehle

ZweckBefehl
npm-Pakete installieren (exakt nach package-lock.json)make web-deps
Editor bauen (nach internal/webui/dist/)make web

Typen prüfenin web/: npm run typecheck
End-to-End-Tests (Playwright)make e2e – baut alles und startet runnel serve examples/hello auf Port 7399; Tests, die speichern, laufen gegen eine temporäre Kopie auf Port 7398

Regeln

  • Oberfläche nur nach freigegebenem Mockup (Design-Handbuch, Kap. 9).
  • Nur Tokens: Farben über die semantischen Tailwind-Klassen (bg-background, text-muted-foreground, border-border, bg-warning-soft …), keine Hex-Werte, keine dark:-Varianten – das Farbschema wechselt über <html data-theme> und die Tokens. Schriftgrößen text-2xs … text-xl, Basis 13 px.
  • Texte englisch (ADR 0015), Ton nach Handbuch Kap. 7; Zustände nie nur über Farbe, immer mit Symbol oder Text.
  • Keine externen Ressourcen: Der Server setzt eine Content-Security-Policy, die nur eigene Dateien und die eigene API erlaubt. Schriften, Icons und Bilder werden mitgebaut.
  • Abhängigkeiten nur mit Begründung im PR, Versionen exakt (--save-exact), Lizenz MIT-kompatibel. Was in den Build eingeht, landet automatisch in THIRD_PARTY_NOTICES.txt und in der SBOM; Werkzeuge gehören in devDependencies.
  • Tests: Jede sichtbare Funktion bekommt einen Playwright-Test gegen den echten Server (web/e2e/).

Wichtige Abläufe

ThemaUmsetzung
CanvasReact Flow (@xyflow/react); Knoten ActionNode.tsx, Links LinkEdge.tsx. Das Modell kommt aus /validate (gesendet wird der angezeigte Text), nicht aus einem YAML-Parser im Browser. Pipelines öffnen ebenfalls als Canvas.
BearbeitenJede Änderung auf dem Canvas geht an POST /workflows/edit bzw. /pipelines/edit; der Server ändert den Text zeilengenau. Rückgängig und Wiederholen speichern Textstände (bis 100).
YAML-AnsichtCodeMirror 6 mit eigener Hervorhebung (yaml.ts), Suchen und Ersetzen; getippter Text geht nach 0,5 s Pause als ein Schritt in denselben Verlauf wie der Canvas. Vervollständigung und Hover aus den Schemas (yamlAssist.ts).
EigenschaftenPropertiesPanel.tsx: Formular aus dem Schema des Descriptors – Auswahl für enum, Kontrollkästchen, Dauer, mehrzeiliger Text, Listen als Chips, Tabelle oder Karten; Feldauswahl bei runnel-field, Abschnitt „Help“ aus dem example.
AusdrückeExpressionInput.tsx (CodeMirror 6) für alle Textfelder unter with: und Link-Bedingungen: Hervorhebung, Vorschläge, Signaturhilfe, Fehler an der Stelle; größerer Editor mit Referenz über Strg+Umschalt+E.
SpeichernPUT /files/{path} mit dem ETag des geladenen Stands; 412 öffnet den Konfliktdialog (Cancel, Reload, Overwrite). Gespeichert wird als UTF-8.
Ausführen„Run“ (F5) startet die gespeicherte Datei über POST /runs; run.ts folgt dem Lauf über /events. Knoten zeigen Statusleiste und Symbol, der aktive Link „strömt“ (aus bei prefers-reduced-motion). Tab „Log“ unter dem Canvas.
Datenvorschau„Preview data“ im Panel eines Transforms: POST /preview, Tab „Preview“ mit Tabelle oder JSON je Ausgabe oder Link.
Link teilenEin Baustein aus der Palette, über einen Link gezogen, kommt zwischen dessen Enden (linkAt in Canvas.tsx); „Insert step…“ im Menü des Links sucht über die Typen der Palette. splitLink in workflow.ts: Bedingung und Fehler-Link bleiben am ersten Link, Info-Link und loop am zweiten; ein Schritt für Rückgängig.
DateienExplorer.tsx: anlegen aus Vorlagen, umbenennen, verschieben per Ziehen und Ablegen, löschen mit Rückfrage; vorher prüft /references, welche Dateien darauf verweisen. Tiefere Ordner starten geschlossen, der Browser merkt sich den Stand je Projekt. Binärdateien (z. B. Programme von Plugins) stehen gedimmt und öffnen keinen Tab.
Läufe„Runs“ in der Kopfzeile öffnet die Run-Historie als Tab (RunsView.tsx, runs.ts): nach Tagen gruppiert, Filter für Status, Datei und Trigger, live. „Open on canvas“ zeigt einen früheren Lauf mit Status und Log auf dem Canvas, mit älterem/neuerem Lauf der Datei und Hinweis, wenn die Datei sich seitdem geändert hat.
PluginsPluginView.tsx, plugins.ts (GET /plugins): Plugin-Ordner im Explorer mit Version und Stand, plugin.yaml als Übersicht, Dialog „Trust plugin“ mit Hash, „Untrust“, „Try again“. Schritte eines nicht nutzbaren Plugins zeigen im Panel und unter „Problems“ „Open plugin …“. Ändert sich der Stand, lädt refreshCatalog() Palette und Panel neu.
FormulareConnections (ConnectionForm.tsx), Trigger (TriggerForm.tsx), Environments und project.yaml (SettingsForm.tsx) öffnen als Formular mit Umschalter auf YAML; Felder aus dem Schema, Änderungen über /forms/edit. Connections mit „Test connection“, Trigger mit „Run target now“; Secret-Felder zeigen den Stand je Environment aus /secrets.
Ohne ProjektRoot.tsx fragt zuerst GET /project. Hat der Ordner des Servers kein Projekt, erscheint statt des Editors die Startseite StartPage.tsx („No project here“, Ordner des Servers, Name mit Vorschlag, „Create project“; bei nicht leerem Ordner mit „Add to the existing files“ wie runnel init --force). Danach öffnet der Beispiel-Workflow.
Bilder und BinärdateienBilder (PNG, JPEG, GIF, WebP; SVG nur als <img>) öffnen in ImageView.tsx mit Abmessungen und Dateigröße. Andere Binärdateien beantwortet GET /files mit 415; ihr Tab zeigt „Binary file – can't be shown“.
TabsBei vielen offenen Dateien werden die Tabs schmaler (mindestens 160 px) und die Leiste scrollt; eine Liste aller offenen Dateien hilft beim Wechseln.
FehlergrenzenErrorBoundary.tsx: Ein Fehler beim Zeichnen bleibt in seinem Bereich – je Tab, in der Seitenleiste und als letzte Stufe um die ganze Oberfläche.

Developer docs · User interface

Developing the editor

The editor is a React application in web/. It is built, embedded into runnel.exe and served by runnel serve at http://127.0.0.1:7300/. It talks to the server only through the server API.

Source (German): docs/dev/EDITOR.md – including the full table describing the behavior of every feature. Design: corporate design, approved mockups.

Prerequisites

  • Go as specified in go.mod
  • Node.js 22 LTS (web/.node-version) with npm

Without Node, make build-go builds an executable without the editor; runnel serve then shows a notice at /. The Go tests don't need an editor build.

Rules

  • UI only after an approved mockup (design handbook, ch. 9).
  • Tokens only: colors via the semantic Tailwind classes (bg-background, text-muted-foreground, border-border, bg-warning-soft …), no hex values, no dark: variants – the color scheme switches via <html data-theme> and the tokens. Font sizes text-2xs … text-xl, base 13 px.
  • English texts (ADR 0015), tone per handbook ch. 7; never show state by color alone, always with a symbol or text.
  • No external resources: the server sets a content security policy that only allows its own files and its own API. Fonts, icons and images are bundled.
  • Dependencies only with a reason in the PR, exact versions (--save-exact), MIT-compatible license. Whatever goes into the build ends up in THIRD_PARTY_NOTICES.txt and the SBOM automatically; tools belong in devDependencies.
  • Tests: every visible feature gets a Playwright test against the real server (web/e2e/).

Key behavior

TopicImplementation
CanvasReact Flow (@xyflow/react); nodes ActionNode.tsx, links LinkEdge.tsx. The model comes from /validate (the displayed text is sent), not from a YAML parser in the browser. Pipelines open as a canvas too.
EditingEvery change on the canvas goes to POST /workflows/edit or /pipelines/edit; the server changes the text line by line. Undo and redo store text states (up to 100).
YAML viewCodeMirror 6 with its own highlighting (yaml.ts), find and replace; typed text joins the same history as the canvas as one step after a 0.5 s pause. Completion and hover from the schemas (yamlAssist.ts).
PropertiesPropertiesPanel.tsx: a form from the descriptor's schema – selection for enum, checkboxes, durations, multi-line text, lists as chips, table or cards; field selection for runnel-field, a “Help” section from the example.
ExpressionsExpressionInput.tsx (CodeMirror 6) for every text field under with: and for link conditions: highlighting, suggestions, signature help, errors in place; a larger editor with reference via Ctrl+Shift+E.
SavingPUT /files/{path} with the ETag of the loaded state; 412 opens the conflict dialog (Cancel, Reload, Overwrite). Files are saved as UTF-8.
Running“Run” (F5) starts the saved file via POST /runs; run.ts follows the run via /events. Nodes show a status bar and symbol, the active link “flows” (off with prefers-reduced-motion). “Log” tab below the canvas.
Data preview“Preview data” in a transform's panel: POST /preview, a “Preview” tab with table or JSON per output or link.
Splitting a linkA component dragged from the palette over a link lands between its ends (linkAt in Canvas.tsx); “Insert step…” in the link's menu searches the palette types. splitLink in workflow.ts: condition and error link stay on the first link, info link and loop on the second; one undo step.
FilesExplorer.tsx: create from templates, rename, move by drag and drop, delete with confirmation; /references first checks which files point to it. Deeper folders start collapsed; the browser remembers the state per project. Binary files (e.g. plugin programs) are dimmed and open no tab.
Runs“Runs” in the header opens the run history as a tab (RunsView.tsx, runs.ts): grouped by day, filters for status, file and trigger, live. “Open on canvas” shows an earlier run with status and log on the canvas, with older/newer run of the file and a hint if the file has changed since.
PluginsPluginView.tsx, plugins.ts (GET /plugins): plugin folders in the explorer with version and state, plugin.yaml as an overview, “Trust plugin” dialog with hash, “Untrust”, “Try again”. Steps of an unusable plugin show “Open plugin …” in the panel and under “Problems”. When the state changes, refreshCatalog() reloads palette and panel.
FormsConnections (ConnectionForm.tsx), triggers (TriggerForm.tsx), environments and project.yaml (SettingsForm.tsx) open as a form with a switch to YAML; fields from the schema, changes via /forms/edit. Connections with “Test connection”, triggers with “Run target now”; secret fields show the state per environment from /secrets.
Without a projectRoot.tsx first asks GET /project. If the server's folder has no project, the start page StartPage.tsx appears instead of the editor (“No project here”, the server's folder, name with a suggestion, “Create project”; for a folder that is not empty with “Add to the existing files” like runnel init --force). Afterwards the example workflow opens.
Images and binary filesImages (PNG, JPEG, GIF, WebP; SVG only as <img>) open in ImageView.tsx with dimensions and file size. GET /files answers other binary files with 415; their tab shows “Binary file – can't be shown”.
TabsWith many open files the tabs get narrower (at least 160 px) and the bar scrolls; a list of all open files helps switching.
Error boundariesErrorBoundary.tsx: a rendering error stays in its area – per tab, in the sidebar and, as the last level, around the whole UI.
