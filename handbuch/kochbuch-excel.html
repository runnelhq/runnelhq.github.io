Handbuch · Kochbuch

Excel lesen und schreiben

Liest Bestellungen aus einer Excel-Mappe, schreibt sie als CSV-Datei und als neue, formatierte Mappe. Fehlerhafte Zeilen gehen in eine eigene Datei.

Bausteine
excel.input, excel.output, csv.output
Anmeldung
keine – nur Dateien
Stand
Geprüft am 24.11.2026 mit runnel validate und vollständig ausgeführt mit den Beispieldaten des Rezepts.

Voraussetzungen

Keine Konten oder Schlüssel nötig.

Dateien

project.yaml
# Recipe: read orders from an Excel workbook, write a CSV file and a formatted workbook.
kind: Project
apiVersion: runnel/v1
name: excel
description: Orders from Excel to CSV and back to Excel
pipelines/orders.pipeline.yaml
# Reads orders from data/orders.xlsx and writes them to a CSV file and a new workbook.
# - "read": sheet "Bestellungen", the table starts in A3 (a title is above it);
#   emptyRows: stop ends it before the sum below. Numbers, dates and true/false come
#   typed from Excel; fields: chooses the columns and checks their types.
# - An order with #N/A in Betrag goes over the error link to REJECTED instead of
#   stopping the pipeline.
# - "workbook": header bold and frozen, Betrag with an Excel number format, dates stay
#   dates. ifExists: sheet would replace only this sheet in an existing workbook.
kind: Pipeline
apiVersion: runnel/v1
name: orders
parameters:
  - name: OUTPUT
    description: CSV file to write
    default: out/excel-orders.csv
  - name: REJECTED
    description: CSV file for orders with errors
    default: out/excel-rejected.csv
  - name: WORKBOOK
    description: Excel workbook to write
    default: out/excel-orders.xlsx
transforms:
  - id: read
    type: excel.input
    with:
      path: data/orders.xlsx
      sheet: Bestellungen
      range: A3
      emptyRows: stop
      fields:
        - { name: Nr, type: int }
        - { name: Kunde }
        - { name: Betrag, type: decimal }
        - { name: Datum, type: date }
        - { name: Bezahlt, type: bool }
  - id: write
    type: csv.output
    with:
      path: ${OUTPUT}
      delimiter: ";"
      fields:
        - { name: Nr }
        - { name: Kunde }
        - { name: Betrag, format: "#.##0,00" }
        - { name: Datum, format: dd.MM.yyyy }
        - { name: Bezahlt }
  - id: workbook
    type: excel.output
    with:
      path: ${WORKBOOK}
      sheet: Bestellungen
      fields:
        - { name: Nr }
        - { name: Kunde }
        - { name: Betrag, excelFormat: "#,##0.00 \"€\"" }
        - { name: Datum, format: dd.MM.yyyy }
        - { name: Bezahlt }
  - id: rejected
    type: csv.output
    with:
      path: ${REJECTED}
      delimiter: ";"
links:
  - { from: read, to: write }
  - { from: read, to: workbook }
  - { from: read, to: rejected, type: error }
workflows/export.workflow.yaml
# Creates the output folder and runs the pipeline; csv.output and the other outputs
# do not create missing folders. The counts of the pipeline are the outputs.
#   runnel run workflows/export.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: export
outputs:
  - name: WRITTEN
    type: integer
    value: "{{ results.orders.output.transforms.write.written }}"
  - name: REJECTED
    type: integer
    value: "{{ results.orders.output.errors }}"
actions:
  - id: start
    type: core.start
  - id: folder
    type: file.mkdir
    with:
      path: out
  - id: orders
    type: core.run-pipeline
    with:
      pipeline: pipelines/orders.pipeline.yaml
links:
  - { from: start, to: folder }
  - { from: folder, to: orders }

Die Beispielmappe data/orders.xlsx hat über der Tabelle einen Titel und darunter eine Summenzeile; Bestellung 1004 enthält #N/A im Betrag und landet über den Fehler-Link in out/excel-rejected.csv. Der Workflow legt den Ordner out an, weil die Ausgaben fehlende Ordner nicht erzeugen.

Ausführen

Im Ordner des Rezepts (PowerShell):

PowerShell
runnel run workflows/export.workflow.yaml

Anpassen

  • sheet und range an die eigene Mappe anpassen: range: A3 heißt, die Tabelle beginnt mit der Kopfzeile in A3; emptyRows: stop endet an der ersten leeren Zeile, etwa vor einer Summenzeile.
  • Zahlen, Daten und Wahrheitswerte kommen aus Excel bereits typisiert; fields wählt nur die Spalten und prüft die Typen. Spalten mit anderem Namen holt from.
  • Beim Schreiben bleibt eine Zahl eine Zahl: format nimmt ein Runnel-Muster wie #.##0,00, excelFormat einen eigenen Excel-Code wie #,##0.00 "€". Mit ifExists: sheet ersetzt Runnel nur ein Blatt einer vorhandenen Mappe.

Reading and writing Excel

Reads orders from an Excel workbook and writes them as a CSV file and as a new, formatted workbook. Faulty rows go into a separate file.

Components
excel.input, excel.output, csv.output
Sign-in
none – files only
Status
Checked on 2026-11-24 with runnel validate and run completely with the recipe's sample data.

Prerequisites

No accounts or keys needed.

Files

project.yaml
# Recipe: read orders from an Excel workbook, write a CSV file and a formatted workbook.
kind: Project
apiVersion: runnel/v1
name: excel
description: Orders from Excel to CSV and back to Excel

The sample workbook data/orders.xlsx has a title above the table and a sum row below it; order 1004 contains #N/A as amount and goes over the error link into out/excel-rejected.csv. The workflow creates the folder out because the outputs don't create missing folders.

Running

In the recipe folder (PowerShell):

PowerShell
runnel run workflows/export.workflow.yaml

Adapting

  • Adapt sheet and range to your workbook: range: A3 means the table starts with its header in A3; emptyRows: stop ends at the first empty row, e.g. before a sum row.
  • Numbers, dates and booleans already come typed from Excel; fields only picks the columns and checks their types. Columns with another name are taken with from.
  • When writing, a number stays a number: format takes a Runnel pattern such as #.##0,00, excelFormat a custom Excel code such as #,##0.00 "€". With ifExists: sheet Runnel replaces just one sheet of an existing workbook.
