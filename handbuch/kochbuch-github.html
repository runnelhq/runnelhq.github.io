Handbuch · Kochbuch

GitHub

Liest alle offenen Issues eines Repositorys Seite für Seite und legt bei Bedarf ein neues Issue an – etwa wenn ein nächtlicher Import scheitert.

API
GitHub REST API, Version 2022-11-28
Anmeldung
Personal Access Token als bearer
Stand
Runnel-seitig geprüft am 27.11.2026 mit Runnel v0.1.0-alpha.13: runnel validate und Ausführung gegen einen Testserver, der die API nachbildet. Gegen die echte API noch nicht ausgeführt – Endpunkte und Felder nach der Dokumentation des Anbieters (Stand 11/2026).

Voraussetzungen

NameArtBedeutung
GITHUB_TOKENSecretFine-grained Personal Access Token mit Lesezugriff auf Issues (zum Anlegen: Schreibzugriff)

Secrets kommen hier aus Umgebungsvariablen (secretStore: env in project.yaml); für den Dienst die Variable beim Dienstkonto setzen. Ohne diese Zeile liest Runnel sie aus dem lokalen Secret-Store: runnel secret set NAME.

Dateien

project.yaml
# Recipe: GitHub REST API with a personal access token from GITHUB_TOKEN.
kind: Project
apiVersion: runnel/v1
name: github
description: Issues of a GitHub repository
secretStore: env
variables:
  GITHUB_URL: https://api.github.com/
connections/github.yaml
kind: Connection
apiVersion: runnel/v1
name: github
description: GitHub REST API with a token
type: http
with:
  baseUrl: ${GITHUB_URL}
  auth: bearer
  token: ${secret:GITHUB_TOKEN}
  headers:
    Accept: application/vnd.github+json
    X-GitHub-Api-Version: "2022-11-28"
workflows/open-issues.workflow.yaml
# Reads all open issues of a repository, page by page (GitHub names the next page in
# the header Link), and logs them.
#   runnel run --param REPO=owner/name workflows/open-issues.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: open-issues
parameters:
  - name: REPO
    description: Repository as owner/name
    required: true
outputs:
  - name: COUNT
    type: int
    value: "{{ results.fetch.output.count }}"
actions:
  - id: start
    type: core.start
  - id: fetch
    type: http.request
    with:
      connection: github
      url: repos/${REPO}/issues
      query:
        state: open
      paginate:
        style: link
        size: 100
        sizeParam: per_page
      timeout: 30s
  - id: report
    type: core.log
    forEach: "{{ results.fetch.output.items }}"
    with:
      message: "#{{ row.number }} {{ row.title }}"
links:
  - { from: start, to: fetch }
  - { from: fetch, to: report, when: "{{ results.fetch.output.count > 0 }}" }
workflows/create-issue.workflow.yaml
# Creates an issue; other workflows call it with core.run-workflow.
#   runnel run --param REPO=owner/name --param TITLE="Import failed" workflows/create-issue.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: create-issue
parameters:
  - name: REPO
    required: true
  - name: TITLE
    required: true
  - name: BODY
    default: Created by Runnel
outputs:
  - name: NUMBER
    type: int
    value: "{{ results.create.output.body.number }}"
  - name: URL
    value: "{{ results.create.output.body.html_url }}"
actions:
  - id: start
    type: core.start
  - id: create
    type: http.request
    with:
      connection: github
      method: POST
      url: repos/${REPO}/issues
      body:
        title: "${TITLE}"
        body: "${BODY}"
links:
  - { from: start, to: create }

GitHub nennt die nächste Seite im Header Link, daher style: link. Ohne Token funktionieren öffentliche Repositories mit deutlich weniger Anfragen pro Stunde – dafür auth und token in der Connection weglassen.

Ausführen

Im Ordner des Rezepts (PowerShell):

PowerShell
$env:GITHUB_TOKEN = "github_pat_…"
runnel run --param REPO=owner/name workflows/open-issues.workflow.yaml
runnel run --param REPO=owner/name --param TITLE="Import failed" workflows/create-issue.workflow.yaml

Anpassen

  • Andere Endpunkte wie repos/${REPO}/pulls oder repos/${REPO}/releases nutzen dieselbe Connection und dieselbe Paginierung.
  • Für GitHub Enterprise Server GITHUB_URL auf https://<host>/api/v3/ setzen.
  • maxItems (Standard 10.000) begrenzt die gelesenen Issues; mehr ist ein Fehler.

User guide · Cookbook

GitHub

Reads all open issues of a repository page by page and creates a new issue when needed – e.g. when a nightly import fails.

API
GitHub REST API, version 2022-11-28
Sign-in
Personal access token as bearer
Status
Checked on the Runnel side on 2026-11-27 with Runnel v0.1.0-alpha.13: runnel validate and runs against a test server that mimics the API. Not yet run against the real API – endpoints and fields per the provider's documentation (as of 11/2026).

Prerequisites

NameKindMeaning
GITHUB_TOKENSecretFine-grained personal access token with read access to issues (to create: write access)

Secrets come from environment variables here (secretStore: env in project.yaml); for the service, set the variable for the service account. Without this line Runnel reads them from the local secret store: runnel secret set NAME.

Running

In the recipe folder (PowerShell):

PowerShell
$env:GITHUB_TOKEN = "github_pat_…"
runnel run --param REPO=owner/name workflows/open-issues.workflow.yaml
runnel run --param REPO=owner/name --param TITLE="Import failed" workflows/create-issue.workflow.yaml

Adapting

  • Other endpoints such as repos/${REPO}/pulls or repos/${REPO}/releases use the same connection and pagination.
  • For GitHub Enterprise Server, set GITHUB_URL to https://<host>/api/v3/.
  • maxItems (default 10,000) limits the issues read; more is an error.
