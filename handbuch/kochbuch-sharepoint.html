Handbuch · Kochbuch

SharePoint (Microsoft Graph)

Lädt ZIP-Dateien aus einer SharePoint-Dokumentbibliothek herunter, entpackt sie und liest die enthaltenen CSV-Dateien in eine Datei. Das Rezept zeigt die Anmeldung mit OAuth2 (Client Credentials) und den Download mit saveTo.

API
Microsoft Graph, Inhalt einer Datei herunterladen
Anmeldung
OAuth2 Client Credentials einer in Microsoft Entra registrierten Anwendung
Stand
Runnel-seitig geprüft am 27.11.2026 mit Runnel v0.1.0-alpha.13: runnel validate und Ausführung gegen einen Testserver mit Token-Abruf, Weiterleitung und ZIP-Download. Gegen Microsoft Graph noch nicht ausgeführt – nach der Dokumentation von Microsoft (Stand 11/2026).

Voraussetzungen

NameArtBedeutung
GRAPH_TENANTVariableTenant, z. B. contoso.onmicrosoft.com
GRAPH_CLIENT_IDVariableAnwendungs-ID (Client-ID) der registrierten Anwendung
SHAREPOINT_SITEVariableSite als host:/pfad:, z. B. contoso.sharepoint.com:/sites/Finance:
GRAPH_CLIENT_SECRETSecretGeheimer Clientschlüssel der Anwendung

Secrets kommen hier aus Umgebungsvariablen (secretStore: env in project.yaml); für den Dienst die Variable beim Dienstkonto setzen. Ohne diese Zeile liest Runnel sie aus dem lokalen Secret-Store: runnel secret set NAME.

Dateien

project.yaml
# Recipe: files from SharePoint Online over Microsoft Graph.
# Tenant, application (client) id and site come from here (replace with your own); the
# client secret comes from the environment variable GRAPH_CLIENT_SECRET.
kind: Project
apiVersion: runnel/v1
name: sharepoint
description: ZIP files with orders from SharePoint Online
secretStore: env
variables:
  GRAPH_URL: https://graph.microsoft.com/v1.0/
  GRAPH_TOKEN_URL: https://login.microsoftonline.com/${GRAPH_TENANT}/oauth2/v2.0/token
  GRAPH_TENANT: contoso.onmicrosoft.com
  GRAPH_CLIENT_ID: 00000000-0000-0000-0000-000000000000
  SHAREPOINT_SITE: "contoso.sharepoint.com:/sites/Finance:"
connections/sharepoint.yaml
# Needs an application registered in Microsoft Entra with the application permission
# Sites.Selected (access granted per site, recommended) or Files.Read.All.
kind: Connection
apiVersion: runnel/v1
name: sharepoint
description: SharePoint Online over Microsoft Graph
type: http
with:
  baseUrl: ${GRAPH_URL}
  auth: oauth2
  tokenUrl: ${GRAPH_TOKEN_URL}
  clientId: ${GRAPH_CLIENT_ID}
  clientSecret: ${secret:GRAPH_CLIENT_SECRET}
  scope: https://graph.microsoft.com/.default
workflows/orders.workflow.yaml
# Downloads ZIP files from several SharePoint Online paths, unpacks them and reads the
# CSV files they hold: one run of file.workflow.yaml per path (forEach),
# one after the other, since all of them append to out/sharepoint-orders.csv.
# Needs the connection sharepoint (see there) and SHAREPOINT_SITE in project.yaml:
#   runnel run -v workflows/orders.workflow.yaml
#   runnel run -v --param 'PATHS=["Exports/2026/orders-north.zip"]' workflows/orders.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: orders
parameters:
  - name: PATHS
    type: json
    description: Paths of the ZIP files in the document library of the site
    default: '["Exports/orders-north.zip", "Exports/orders-south.zip"]'
outputs:
  - name: ROWS
    type: int
    value: "{{ sum(map(results.files.output.items, .output.ROWS)) }}"
actions:
  - id: start
    type: core.start
  - id: prepare
    type: file.mkdir
    with:
      path: out
  - id: clear
    type: file.delete
    with:
      path: out/sharepoint-orders.csv
  - id: files
    type: core.run-workflow
    forEach: "{{ params.PATHS }}"
    with:
      workflow: workflows/file.workflow.yaml
      params:
        PATH: "{{ row }}"
  - id: report
    type: core.log
    with:
      message: "{{ len(params.PATHS) }} files, {{ sum(map(results.files.output.items, .output.ROWS)) }} rows written to out/sharepoint-orders.csv"
links:
  - { from: start, to: prepare }
  - { from: prepare, to: clear }
  - { from: clear, to: files }
  - { from: files, to: report }
workflows/file.workflow.yaml
# One ZIP file from SharePoint Online, called by orders.workflow.yaml:
# download it with http.request and saveTo (Graph answers /content with a redirect to the
# download; the token does not go along), unpack the CSV files, read each of them.
#   runnel run -v --param PATH=Exports/orders-north.zip workflows/file.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: file
parameters:
  - name: PATH
    description: Path of the ZIP file in the document library, e.g. Exports/orders-north.zip
    required: true
outputs:
  - name: ROWS
    type: int
    value: "{{ sum(map(results.read.output.items, len(.output.records))) }}"
actions:
  - id: start
    type: core.start
  - id: download
    type: http.request
    with:
      connection: sharepoint
      url: "sites/${SHAREPOINT_SITE}/drive/root:/${PATH}:/content"
      saveTo: inbox/${PATH}
      timeout: 10m
  - id: unpack
    type: archive.extract
    with:
      source: "{{ results.download.output.path }}"
      target: inbox/unpacked/${PATH}
      pattern: "*.csv"
      ifExists: replace
  - id: read
    type: core.run-pipeline
    forEach: "{{ results.unpack.output }}"
    with:
      pipeline: pipelines/orders.pipeline.yaml
      params:
        FILE: "{{ row }}"
links:
  - { from: start, to: download }
  - { from: download, to: unpack }
  - { from: unpack, to: read }
pipelines/orders.pipeline.yaml
# Reads one CSV file of a ZIP from SharePoint and appends its rows to
# out/sharepoint-orders.csv; the rows also go back to the workflow (core.to-result).
kind: Pipeline
apiVersion: runnel/v1
name: orders
parameters:
  - name: FILE
    description: Unpacked CSV file
    required: true
transforms:
  - id: read
    type: csv.input
    with:
      path: ${FILE}
      delimiter: ";"
  - id: write
    type: csv.output
    with:
      path: out/sharepoint-orders.csv
      delimiter: ";"
      ifExists: append
  - id: result
    type: core.to-result
links:
  - { from: read, to: write }
  - { from: read, to: result }

Runnel holt das Token selbst und hält es bis kurz vor Ablauf im Speicher. Graph beantwortet …:/content mit einer Weiterleitung zum Download; zu einem anderen Host geht das Token dabei nicht mit. saveTo schreibt die Antwort direkt in eine Datei, ihr Pfad steht in output.path. Die Dateien werden nacheinander verarbeitet (forEach ohne parallel), weil alle an dieselbe CSV-Datei anhängen.

Ausführen

Im Ordner des Rezepts (PowerShell):

PowerShell
$env:GRAPH_CLIENT_SECRET = "…"
runnel run -v workflows/orders.workflow.yaml
runnel run -v --param 'PATHS=["Exports/2026/orders-north.zip"]' workflows/orders.workflow.yaml

Anpassen

  • In Microsoft Entra eine Anwendung registrieren und ihr die Anwendungsberechtigung Sites.Selected geben (Zugriff je Site freigeben, empfohlen) oder Files.Read.All; einen geheimen Clientschlüssel anlegen.
  • Die Pfade der Dateien stehen im Parameter PATHS (JSON-Liste), relativ zur Dokumentbibliothek der Site.
  • Für andere Dateiarten den Schritt unpack weglassen und die Pipeline direkt mit results.download.output.path aufrufen.
  • Andere Graph-Endpunkte (Mail, Teams, Benutzer) nutzen dieselbe Connection; Listen mit paginate: { style: url, next: "@odata.nextLink", items: value }.

User guide · Cookbook

SharePoint (Microsoft Graph)

Downloads ZIP files from a SharePoint document library, unpacks them and reads the CSV files inside into one file. The recipe shows OAuth2 sign-in (client credentials) and downloading with saveTo.

API
Microsoft Graph, download a file's content
Sign-in
OAuth2 client credentials of an application registered in Microsoft Entra
Status
Checked on the Runnel side on 2026-11-27 with Runnel v0.1.0-alpha.13: runnel validate and runs against a test server with token request, redirect and ZIP download. Not yet run against Microsoft Graph – per Microsoft's documentation (as of 11/2026).

Prerequisites

NameKindMeaning
GRAPH_TENANTVariableTenant, e.g. contoso.onmicrosoft.com
GRAPH_CLIENT_IDVariableApplication (client) ID of the registered application
SHAREPOINT_SITEVariableSite as host:/path:, e.g. contoso.sharepoint.com:/sites/Finance:
GRAPH_CLIENT_SECRETSecretClient secret of the application

Secrets come from environment variables here (secretStore: env in project.yaml); for the service, set the variable for the service account. Without this line Runnel reads them from the local secret store: runnel secret set NAME.

Runnel fetches the token itself and keeps it in memory until shortly before it expires. Graph answers …:/content with a redirect to the download; the token does not go along to another host. saveTo writes the response straight into a file, its path is in output.path. Files are processed one after the other (forEach without parallel) because all of them append to the same CSV file.

Running

In the recipe folder (PowerShell):

PowerShell
$env:GRAPH_CLIENT_SECRET = "…"
runnel run -v workflows/orders.workflow.yaml
runnel run -v --param 'PATHS=["Exports/2026/orders-north.zip"]' workflows/orders.workflow.yaml

Adapting

  • Register an application in Microsoft Entra and give it the application permission Sites.Selected (access granted per site, recommended) or Files.Read.All; create a client secret.
  • The file paths are in the parameter PATHS (JSON list), relative to the site's document library.
  • For other file types, drop the unpack step and call the pipeline directly with results.download.output.path.
  • Other Graph endpoints (mail, Teams, users) use the same connection; lists with paginate: { style: url, next: "@odata.nextLink", items: value }.
