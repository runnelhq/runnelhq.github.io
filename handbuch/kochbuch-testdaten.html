Handbuch · Kochbuch

Testdaten (Plugin)

Erzeugt 1.000 Testkunden mit Namen, Adressen, IBAN und Geburtsdatum und pseudonymisiert echte Kundendaten: Gleiche Kundennummern bekommen dieselbe Ersatznummer, auch über Tabellen und Läufe hinweg. Mit dem Plugin faker.

Plugin
runnelhq/plugin-faker: Eingabe faker.rows, Transform faker.fill, Action faker.value; gebaut mit dem Rust-SDK
Anmeldung
keine – rechnet nur lokal
Stand
Geprüft am 27.11.2026 mit den Releases Runnel v0.1.0-alpha.13 und plugin-faker 0.2.0: runnel validate und vollständig ausgeführt; zwei Läufe mit demselben PSEUDONYM_SEED ergeben dieselben Dateien.

Voraussetzungen

NameArtBedeutung
plugins/fakerPluginArchiv von den Releases nach plugins/ entpacken und mit runnel plugins trust freigeben – siehe Plugins installieren
PSEUDONYM_SEEDVariableSchlüssel der Pseudonyme, eine ganze Zahl – als Umgebungsvariable, nie im Projekt

Dateien

project.yaml
kind: Project
apiVersion: runnel/v1
name: testdaten
description: Generates test data and pseudonymizes customer data with the plugin faker
variables:
  # Key of the pseudonyms: whoever knows it can trace replacements back by trying inputs.
  # Set it as an environment variable, never in the project.
  PSEUDONYM_SEED: ${env:PSEUDONYM_SEED}
data/customers.csv
customerNo;firstName;lastName;email;city;revenue
4711;Anna;Müller;anna.mueller@firma-a.de;Köln;1250,00
4712;Jens;Schmidt;j.schmidt@firma-b.de;Bonn;980,50
4713;Eva;Weber;eva.weber@firma-c.de;Köln;
4711;Anna;Müller;anna.mueller@firma-a.de;Köln;310,00
pipelines/customers.pipeline.yaml
kind: Pipeline
apiVersion: runnel/v1
name: customers
description: Generates 1,000 test customers; the same seed gives the same data on every system
parameters:
  - name: COUNT
    type: int
    default: "1000"
transforms:
  - id: fake
    type: faker.rows
    with:
      count: ${COUNT}
      locale: de
      seed: 42
      fields:
        - { name: customerNo, kind: pattern, pattern: "KD-#####" }
        - { name: salutation, kind: salutation }
        - { name: firstName, kind: firstName }
        - { name: lastName, kind: lastName }
        - { name: email, kind: email, from: "firstName, lastName" }
        - { name: street, kind: street }
        - { name: houseNumber, kind: houseNumber }
        - { name: postcode, kind: postcode }
        - { name: city, kind: city }
        - { name: birthDate, kind: birthDate, minAge: 18, maxAge: 90 }
        - { name: iban, kind: iban }
        - { name: segment, kind: pick, values: [A, B, C], weights: [1, 3, 6] }
        - { name: phone, kind: phone, nullRate: 0.2 }
  - id: write
    type: csv.output
    with:
      path: out/test-customers.csv
      delimiter: ";"
links:
  - { from: fake, to: write }
pipelines/pseudonymize.pipeline.yaml
kind: Pipeline
apiVersion: runnel/v1
name: pseudonymize
description: Replaces names, e-mail and customer number of real data; the same input gives the same replacement
transforms:
  - id: read
    type: csv.input
    with:
      path: data/customers.csv
      delimiter: ";"
      fields:
        - { name: customerNo }
        - { name: firstName }
        - { name: lastName }
        - { name: email }
        - { name: city }
        - { name: revenue }                     # passed on unchanged
  - id: pseudo
    type: faker.fill
    with:
      consistent: true
      seed: ${PSEUDONYM_SEED}
      fields:
        - { name: customerNo, kind: pattern, pattern: "KD-#####" }
        - { name: firstName, kind: firstName }
        - { name: lastName, kind: lastName }
        - { name: email, kind: email, from: "firstName, lastName" }
  - id: write
    type: csv.output
    with:
      path: out/customers-pseudonymized.csv
      delimiter: ";"
links:
  - { from: read, to: pseudo }
  - { from: pseudo, to: write }
workflows/generate.workflow.yaml
# Creates the output folder, generates test customers and pseudonymizes data/customers.csv.
#   $env:PSEUDONYM_SEED = "…"
#   runnel run workflows/generate.workflow.yaml
kind: Workflow
apiVersion: runnel/v1
name: generate
outputs:
  - name: GENERATED
    type: int
    value: "{{ results.customers.output.transforms.write.written }}"
  - name: PSEUDONYMIZED
    type: int
    value: "{{ results.pseudonymize.output.transforms.write.written }}"
actions:
  - id: start
    type: core.start
  - id: folder
    type: file.mkdir
    with:
      path: out
  - id: customers
    type: core.run-pipeline
    with:
      pipeline: pipelines/customers.pipeline.yaml
  - id: pseudonymize
    type: core.run-pipeline
    with:
      pipeline: pipelines/pseudonymize.pipeline.yaml
links:
  - { from: start, to: folder }
  - { from: folder, to: customers }
  - { from: customers, to: pseudonymize }

Mit consistent: true hängt der Ersatz nur vom Eingabewert, dem Namen des Feldes und seed ab: Kundennummer 4711 wird in jeder Zeile und in jeder Tabelle mit gleichem Feldnamen zu derselben Nummer. Wer den Seed kennt, kann Ersatzwerte durch Ausprobieren zurückführen – deshalb kommt er aus einer Umgebungsvariablen. Pseudonymisieren ersetzt nur die genannten Felder; Ort und Umsatz bleiben, die Daten sind also nicht anonym. runnel validate warnt bei seed: ${PSEUDONYM_SEED} „without seed, consistent uses seed 0“, weil die Prüfung den Wert der Variablen nicht kennt; im Lauf gilt der gesetzte Seed.

Ausführen

Im Ordner des Rezepts (PowerShell):

PowerShell
Expand-Archive .\runnel-plugin-faker_<version>_windows_amd64.zip -DestinationPath .\plugins
runnel plugins trust . --plugin faker
$env:PSEUDONYM_SEED = "…"   # eine ganze Zahl
runnel run workflows/generate.workflow.yaml
runnel run --param COUNT=100000 pipelines/customers.pipeline.yaml

Anpassen

  • Felder wählt kind: Personen (firstName, salutation passend zum Vornamen), Adressen mit echten Städten und passender Postleitzahl, iban, bic und vatId mit gültiger Prüfziffer, Zahlen und Daten mit min/max, pick mit Gewichten und pattern wie KD-#####. nullRate erzeugt leere Werte, um Wege für fehlende Daten zu testen.
  • seed macht Testdaten wiederholbar: gleiche Konfiguration, gleiche Daten auf jedem System. Ein neues Feld ändert die anderen nicht. locale: en erzeugt englische Daten.
  • Für einen einzelnen Wert im Workflow, etwa für einen Test: Action faker.value mit kind: iban; das Ergebnis steht in results.<id>.output.

User guide · Cookbook

Test data (plugin)

Generates 1,000 test customers with names, addresses, IBAN and birth date and pseudonymizes real customer data: equal customer numbers get the same replacement, across tables and runs too. With the faker plugin.

Plugin
runnelhq/plugin-faker: input faker.rows, transform faker.fill, action faker.value; built with the Rust SDK
Sign-in
none – computes locally only
Status
Checked on 2026-11-27 with the releases Runnel v0.1.0-alpha.13 and plugin-faker 0.2.0: runnel validate and run completely; two runs with the same PSEUDONYM_SEED give the same files.

Prerequisites

plugins/fakerPluginUnpack the archive from the releases into plugins/ and trust it with runnel plugins trust – see Installing plugins
PSEUDONYM_SEEDVariableKey of the pseudonyms, a whole number – as an environment variable, never in the project

With consistent: true the replacement depends only on the input value, the field name and seed: customer number 4711 becomes the same number in every row and in every table with the same field name. Whoever knows the seed can trace replacements back by trying values – so it comes from an environment variable. Pseudonymizing replaces only the fields named; city and revenue stay, so the data is not anonymous. runnel validate warns “without seed, consistent uses seed 0” for seed: ${PSEUDONYM_SEED} because the check does not know the variable's value; the run uses the seed set.

Running

In the recipe folder (PowerShell):

PowerShell
Expand-Archive .\runnel-plugin-faker_<version>_windows_amd64.zip -DestinationPath .\plugins
runnel plugins trust . --plugin faker
$env:PSEUDONYM_SEED = "…"   # eine ganze Zahl
runnel run workflows/generate.workflow.yaml
runnel run --param COUNT=100000 pipelines/customers.pipeline.yaml

Adapting

  • kind chooses the fields: people (firstName, salutation matching the first name), addresses with real cities and matching postcodes, iban, bic and vatId with valid check digits, numbers and dates with min/max, pick with weights and pattern such as KD-#####. nullRate produces empty values to test paths for missing data.
  • seed makes test data repeatable: same configuration, same data on every system. A new field does not change the others. locale: en produces English data.
  • For a single value in a workflow, e.g. for a test: action faker.value with kind: iban; the result is in results.<id>.output.
