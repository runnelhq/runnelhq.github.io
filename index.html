Ein Vibe-Coding-Projekt

Runnel entsteht überwiegend mit KI: Code, Tests und Dokumentation schreiben KI-Agenten wie Claude Code – nach festen Regeln in AGENTS.md, mit automatischen Tests unter Linux und Windows und Freigabe durch den Maintainer. Vorabversion: bitte vor produktivem Einsatz selbst prüfen.

Warum Runnel

Automatisierung ohne Plattform-Ballast

Runnel verbindet die visuelle Einfachheit von n8n und Make mit dem sauberen Modell von Apache Hop – als schlanke Anwendung, die man per Doppelklick startet.

Eine einzige exe

Kein Node.js, keine JVM, keine externe Datenbank. Kopieren, starten, fertig – auf Wunsch portabel vom USB-Stick oder Netzlaufwerk.

Windows-first

Läuft als Windows-Dienst, schützt Secrets mit DPAPI, versteht UNC-Pfade und Freigaben. Linux-Builds gibt es trotzdem.

Lokal und offline

Deine Daten bleiben in deinem Netz. Keine Cloud, kein Konto, kein Abo – auch im abgeschotteten Firmennetz einsetzbar.

Git-freundlich

Workflows und Pipelines sind lesbare YAML-Dateien: diffen, reviewen, versionieren – wie jeder andere Code.

Editor und Runner

Visuell gestalten im Editor im Browser, headless ausführen in CI und Aufgabenplanung – mit denselben YAML-Dateien.

Zeitplan und HTTP

Trigger starten Workflows nach Zeitplan, im Intervall, bei neuen Dateien im Ordner oder per HTTP – im Netz über HTTPS, mit Antwort aus dem Workflow.

Das Modell

Workflows steuern, Pipelines bewegen Daten

Zwei klare Bausteine statt eines Alles-Graphen. Beide liegen als YAML im Projekt, beide sehen im Editor gleich aus.

Workflow *.workflow.yaml

Actions nacheinander oder parallel ausführen – Dateien holen, HTTP aufrufen, Pipelines starten. Links entscheiden, wie es weitergeht:

  • ✔Erfolg
  • ✖Fehler
  • ∞Immer
  • ƒAusdruck

Pipeline *.pipeline.yaml

Transforms streamen Datensätze parallel durch den Graphen – mit Backpressure und konstantem Speicher, auch bei Millionen Zeilen.

  • CSV · JSON · Excel · XML
  • SQL Server · PostgreSQL · SQLite
  • HTTP
  • Filtern · Berechnen · Joins
examples/hello/workflows/hello.workflow.yaml 
# A small, valid workflow. Check it with:  runnel validate examples/hello
kind: Workflow
apiVersion: runnel/v1
name: hello
description: Greets, waits a moment and reports success or failure.
parameters:
  - name: GREETING
    description: Word to greet with
    enum: [Hello, Hi, Moin]
    default: Hello
outputs:
  - name: MESSAGE
    description: The greeting that was logged
    value: "${GREETING}, ${TARGET}!"
actions:
  - id: start
    type: core.start
  - id: greet
    type: core.log
    with:
      message: "${GREETING}, ${TARGET}! (${STAGE} on ${env:COMPUTERNAME:-this computer}, files in ${OUTBOX})"
  - id: pause
    type: core.wait
    with:
      duration: 1s
  - id: done
    type: core.success
  - id: failed
    type: core.abort
links:
  - { from: start, to: greet }
  - { from: greet, to: pause }
  - { from: pause, to: done }
  - { from: pause, to: failed, when: failure }

Erweitern

Plugins für alles, was nicht in die exe gehört

Ein Plugin ist ein eigenes Programm im Projektordner – in Go, C#, Python oder jeder anderen Sprache. Runnel startet es als Kindprozess und spricht es über JSON-RPC auf stdin/stdout an: kein offener Port, keine Laufzeit im Kern. Seine Actions, Transforms und Connection-Typen stehen im Editor wie die eingebauten.

SDK

sdk-go

Plugins in Go schreiben: Konfiguration als Struct, Schema aus den Tags, Transforms als Strom mit Backpressure, Tests ohne Runnel mit runneltest. Nur die Standardbibliothek, MIT.

go get github.com/runnelhq/sdk-go

Offizielles Plugin

plugin-iban

IBAN und BIC prüfen, IBAN aus Bankleitzahl und Kontonummer bilden – als Actions und als Transform mit Fehler-Link. Rechnet nur lokal.

iban.validate iban.validate-bic iban.create

Offizielles Plugin

plugin-ldap

Active Directory und OpenLDAP: suchen, Anmeldungen prüfen, Einträge ändern und als Datensätze lesen – mit eigenem Connection-Typ und „Test connection“.

ldap.search ldap.authenticate ldap.input

Betrieb

Eine exe für Entwicklung und Betrieb

Vom einmaligen Lauf in der Aufgabenplanung bis zum Dauerbetrieb als Windows-Dienst – immer dieselbe runnel.exe. Alle Befehle zeigt runnel help.

Verfügbar

Prüfen

Workflows, Pipelines und Trigger prüfen – Felder, Links, Variablen, Ausdrücke. Meldungen mit Datei, Zeile und Spalte, ideal für die CI.

> runnel validate D:\flows
Verfügbar

Einmal ausführen

Für Aufgabenplanung, CI und Skripte. Der Exit-Code ist das Ergebnis, Strg+C bricht sauber ab.

> runnel run --env prod workflows\nightly.workflow.yaml
Verfügbar

Editor und Server

Editor im Browser unter 127.0.0.1:7300 – bauen, prüfen, starten und live beobachten. Trigger laufen mit.

> runnel serve D:\flows
Verfügbar

Windows-Dienst

Dauerbetrieb ohne angemeldeten Benutzer – mit Neustart nach Fehlern, Log-Datei und Ereignisanzeige.

> runnel service install D:\flows
Verfügbar

Läufe nachsehen

Jeder Lauf landet in der Run-Historie – aus Editor, Trigger, Dienst und CLI. Status je Schritt und Log, auch nach einem Neustart.

> runnel runs D:\flows --status failed
Verfügbar

Plugins freigeben

Eigene Actions, Transforms und Connection-Typen aus Plugins. Runnel startet ein Plugin erst, wenn es auf diesem Rechner freigegeben ist.

> runnel plugins trust D:\flows
Einordnung

Wo Runnel steht

n8n, Make und Apache Hop sind ausgereifte Werkzeuge mit eigenen Stärken. Runnel setzt bewusst auf einen anderen Schwerpunkt: wenig Betriebsaufwand unter Windows.

MerkmalRunneln8nMakeApache Hop
RuntimeNative BinaryNode.js (+DB)CloudJava (JVM)
Betrieb unter WindowsDoppelklick oder Dienstmöglich, aufwendig– (SaaS)möglich, schwergewichtig
ModellWorkflow + PipelineItem-basierter GraphSzenarioWorkflow + Pipeline
Datenstrom / ETLmittel bis starkeingeschränkteingeschränktstark
SpeicherformatYAML-DateienDatenbank (JSON-Export)CloudXML-Dateien
SaaS-Konnektorengenerisch: HTTP, SQL, Dateien, Skript, Pluginssehr vielesehr vieleeinige

Für viele Cloud-Dienste mit fertigen Konnektoren bleiben n8n und Make die bessere Wahl; für Big Data im Cluster Apache Hop.
